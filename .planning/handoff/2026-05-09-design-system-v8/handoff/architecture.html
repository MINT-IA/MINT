MINT — architecture

Trois couches.
Un seul contrat.

L'app a déjà toutes les briques. Ce qui manque, c'est la hiérarchie. Le LLM décide l'intention. Le code décide la navigation. L'agent ne sort rien sans validation.

01 — Architecture

Trois couches, un flux descendant

L'UI parle à l'orchestrateur conversationnel. L'orchestrateur parle aux modules. Jamais l'inverse.

Couche 1 · Surfaces

UI — 4 onglets, ~50 écrans

Le seul endroit où l'utilisateur saisit, tape, valide. Aucune logique métier.

app.dart
GoRouter — 50+ routes canoniques + redirects legacy + ScopedGoRoute (auth scopes).
MintShell
StatefulShellRoute — Aujourd'hui · Mon argent · Coach · Explorer.
CoachChatScreen
Surface conversationnelle — point d'entrée principal vers la couche 2.
screens/*
Simulateurs, parcours, hubs Explorer, document scan.
Couche 2 · Orchestration

Le LLM propose. Le code dispose.

Aucune navigation issue du chat ne court-circuite cette couche.

CoachOrchestrator
Tier-chain SLM → BYOK → Fallback. ComplianceGuard centralisé sur toutes les sorties.
ChatToolDispatcher
Exécute les tool-calls du LLM. Déléguer au RoutePlanner ou à l'Agent autonome.
RoutePlanner.plan(intentTag)
Retourne RouteDecision : openScreen / openWithWarning / askFirst / conversationOnly.
ScreenRegistry
Source de vérité — route × intentTag × ScreenBehavior × requiredFields.
ReadinessGate
Vérifie les requiredFields du CoachProfile avant d'ouvrir un écran.
SequenceCoordinator
Décide l'étape suivante d'un parcours multi-écrans (Advance / Pause / Retry / Skip / ReEval).
Couche 3 · Modules

Métier pur, sans navigation

Calculent, projettent, génèrent. Lisent CoachProfile. Retournent ScreenReturn.

services/simulators/*
3a, LPP buyback, real interest, compound, leasing, job comparison, divorce, etc.
services/financial_core, lpp_deep, mortgage
Moteurs métier — calculs LSFin/LIFD/LPP/OPP3.
AutonomousAgentService
Lettres + pré-remplissages. SafetyGate (11 règles) + audit log + requiresValidation === true.
document_parser, document_service
Pipeline scan → OCR → extraction → revue utilisateur.

03 — RouteDecision

4 actions possibles

RoutePlanner.plan() retourne toujours l'une des quatre. Aucune navigation hors de ce contrat.

openScreen
Profil complet, requiredFields tous présents. Navigation directe + prefill.
openWithWarning
Profil partiel — l'écran s'ouvre en mode estimation, bandeau d'avertissement.
askFirst
Champs critiques manquants. Le coach pose 1 à 2 questions ciblées avant de re-planifier.
conversationOnly
Pas d'écran adapté, intent inconnu, ou comportement E. Réponse texte.
04 — Machine d'état

Un seul flux, deux issues

Tout passe par CoachOrchestrator. Soit un écran s'ouvre (couche 3 module), soit un artefact est généré (Agent autonome). Toujours validation user à la fin.

05 — Invariants

Six règles non-négociables

01
Le LLM ne décide pas de la navigation. Il propose un intent — le code décide la route.
02
Aucun écran ne s'ouvre sans ReadinessGate. Si requiredFields manquent : askFirst ou openWithWarning.
03
Aucun artefact agent ne sort sans SafetyGate. 11 règles + validation user obligatoire + audit log immuable.
04
Une seule source de vérité par couche : ScreenRegistry, CoachProfile, app.dart.
05
Compliance centralisée. Toutes les sorties LLM passent par ComplianceGuard (LSFin art. 3/8).
06
Privacy-first. Tier 1 = SLM on-device (LPD art. 6). Cloud BYOK uniquement sur opt-in user.
