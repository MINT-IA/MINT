# Phase 94.1 Plan 01 — Narrator-Prompt Fattening

## Objective

Move Stage 3 gate-correct rate from Sonnet 6% (3/50) and Haiku 14% (7/50) — measured live on Anthropic Sonnet + Haiku at Phase 94 Wave 2 — to the target thresholds Sonnet ≥95% and Haiku ≥90%. The mechanical hypothesis from Phase 94 Wave 2 root cause analysis is : the narrator system prompt does not yet teach the `{{cite:<key>}}` placeholder syntax, so the gate (correctly per closed-world contract D-02..D-13) rejects naked numbers and the retry-once flow collapses to fallback at 60-80% rate. Phase 94.1 fattens the prompt with the placeholder grammar + the active 18-key registry vocabulary, then re-runs the unchanged 50-fixture eval pack to measure whether the hypothesis lands.

If thresholds met → re-open `94-03-FLAG-FLIP-PROPOSAL.md` as a GO recommendation and trigger the 4-week staging soak. If not met → document the gap honestly and surface a second-iter scope (without auto-iterating).

## Architectural Decision — Path A vs Path B vs Path C (Hybrid)

Three paths were on the table per the orchestrator brief :

- **Path A** — inject the grammar via a NEW always-on bundle fragment (`CitationGrammarBundle`).
- **Path B** — inject directly into `_NARRATOR_BASE_SYSTEM_PROMPT` (legacy template) AND prepend the same fragment in the bundle compiler.
- **Path C** (Hybrid, chosen) — single source of truth `app/services/coach/citation_grammar.py` exporting `CITATION_GRAMMAR_FRAGMENT: str` (built from `CITATION_REGISTRY` keys), consumed by BOTH a new `CitationGrammarBundle` (always-on) AND a flag-conditional append at the end of `build_narrator_system_prompt`.

### Why Path C (chosen)

1. **The eval harness today calls the LEGACY path** — `tools/eval_narrator.py:182` uses `build_narrator_system_prompt(ctx=None, language=fr, cash_level=3)`. Phase 94 Wave 2 ran with `prompt_builder=legacy` (verified by `94-03-EVAL-RESULTS.md` line 23-25 stdout summaries). If we ONLY ship Path A (bundle fragment) the eval will still send the unchanged legacy prompt to Sonnet + Haiku — the re-eval would NOT measure the fattening. Path B or C is required to make the legacy path teach the grammar.

2. **Path B duplicates the fragment text in two places** — DRY violation. Path C centralises the string in `citation_grammar.py` and both consumers read it.

3. **Byte-identity invariant on the legacy path** — `test_flag_off_byte_identical_to_snapshot` (5 fixtures × 2 test files = 10 byte-identity tests) PIN `build_narrator_system_prompt` to the pre-94 snapshots. If the grammar fragment is unconditionally appended, all 10 tests fail. If it is appended ONLY when `settings.COACH_CITATION_GATE_ENABLED=True`, byte-identity holds for the default `False` (prod) and the eval runs explicitly opt in.

4. **Bundle path always-on integrity** — `tests/bundles/test_bundle_compiler.py:107-130` pin `activated_bundles == ["compliance-narrator", "life-event-router"]`. Adding `citation-grammar` unconditionally to `_ALWAYS_ON` breaks this. The flag-conditional inclusion in `compile_bundles` (skip when `COACH_CITATION_GATE_ENABLED=False`) preserves the existing tests' assumption while opting the bundle in when the gate is active.

5. **eval_narrator must propagate the flag** — today `--gate=on` only triggers the post-process gate ; the system prompt is unchanged. To measure 94.1 fattening, the eval harness MUST set `COACH_CITATION_GATE_ENABLED=True` for the duration of the run when `--gate=on`. We add a thin context manager (or `monkeypatch.setattr`-style toggle) at the top of the run loop.

## Grammar fragment — content blueprint (≤80 lines)

The fragment text MUST :

1. **Open with the cardinal rule** — « POUR CHAQUE chiffre, place `{{cite:<key>}}` directement après le nombre. »
2. **List ALL 18 active keys** from `CITATION_REGISTRY` with their `description_fr` (closed-world vocabulary). Built dynamically from the registry — the test `test_grammar_fragment_lists_all_18_registry_keys` enforces the coupling.
3. **Teach the no-key fallback** — « Si tu n'as pas de clé adaptée, écris « je n'ai pas cette donnée pour l'instant » à la place. N'INVENTE PAS de clé. »
4. **Show 3 verbatim FR examples** :
   - VALID (cited) : `« Le plafond 3a salarié·e est fixé pour 2026 {{cite:r3a_plafond_salarie_2026}}. »`
   - VALID (no-key fallback) : `« Je n'ai pas cette donnée pour l'instant. »`
   - INVALID (uncited) : `« Le plafond 3a est de 7'056 CHF cette année. »` → REJETÉ par la garde, fallback fires.
5. **Match D-09 reprompt grammar verbatim style** — accents 100% FR, FR vocabulary (« pourrait », « envisager », « adapté »), no LSFin banned terms (« garanti », « optimal », « meilleur », « parfait », « sans risque »).
6. **Total length ≤80 lines** (heuristic for token budget — the fragment will inflate the system prompt by ~10% ; current eval baseline is ~10k tokens, so ~+1k tokens budget is OK).

Drafting note : the fragment uses the bundle structure (`## DOCTRINE — CITATION GRAMMAR (closed-world)` heading, list of keys via `- {{cite:<key>}} — {description_fr}`, explicit examples). It does NOT introduce new `{slot}` placeholders (would break `_DECLARED_SLOTS` H4 guard at `bundle_compiler.py:97-105`).

## Result interpretation rules (set BEFORE running eval)

- **PASS (G-A1 + G-A2 + G-B all met)** :
  - Sonnet `gate_correct ≥ 0.95`, Haiku `gate_correct ≥ 0.90`, latency regression `≤ +30%` (Sonnet on-vs-off with retries).
  - Action : update `94-03-FLAG-FLIP-PROPOSAL.md` with new numbers + checkbox flip from `[x] NO-GO + PARTIAL` to `[x] GO recommendation post-Wave-4` (new section). Surface in summary's checkpoint return as `GO recommendation`.

- **PARTIAL (G-A1 OR G-A2 met, but not both ; or thresholds met but G-B not met)** :
  - Action : document the gap in `94.1-EVAL-DELTA.md` ; do NOT recommend prod flip ; propose a 94.2 iter scope (e.g. tighten retry rate path to drop G-B regression).

- **FAIL (Sonnet < 70% OR Haiku < 50% — way short)** :
  - Action : document gap honestly. Hypothesise root cause in `94.1-EVAL-DELTA.md` (e.g. fragment too short / wrong key emphasis / model still ignoring instructions / adjacency rule too tight). Propose 94.2 second-iter WITHOUT auto-running. Surface to orchestrator for GO/NO-GO on iter 2.

- **MARGINAL (70% ≤ Sonnet < 95% OR 50% ≤ Haiku < 90%)** :
  - Per CLAUDE.md §9.7 « I don't know » : document honestly, do NOT call this iteration ready, propose a 94.2 second-iter scope with one specific change hypothesis.
