<domain>
## Phase Boundary

Compile-time skill bundle layer in `services/backend/app/services/coach/bundles/` that emits ONE narrator prompt + filtered tool allowlist + citation allowlist per request. Replaces the 1100-line monolithic `_NARRATOR_BASE_SYSTEM_PROMPT` ([claude_coach_service.py:727](services/backend/app/services/coach/claude_coach_service.py#L727)).

**Adopts**: Anthropic financial-services *patterns* (skill-as-bundle, doctrine-by-domain, citation_allowlist contract) per audit `.planning/audit/codebase-audit-2026-05-10/anthropic-financial-services-agents.md` §7.1 Proposal A.

**Does NOT adopt**: runtime multi-agent topology (no coordinator router, no specialist subagents, no extra LLM hops, no Managed Agents API). Negative ROI pre-TestFlight per audit §4 (+30-60% tokens, +2-4s p50 latency, ×4 prompt-eng surface).

**Out of scope** (deferred):
- Extending extractor schema with 18 `life_event` tokens (Phase 97+ if Stage 3 eval shows mis-routing)
- Compliance-narrator-auditor leaf-worker subagent (audit Proposal B, deferred to Phase 97-98 post-TestFlight)
- Managed Agents API migration (audit Proposal C, ADR only, no commit)

<decisions>
## Implementation Decisions

### Bundle Activation — Intent → Bundle Mapping (Gray Area A)

- **D-01:** Bundle activation reads `ExtractorOutput.intents` ([extractor_schema.py:76-83](services/backend/app/services/coach/extractor_schema.py#L76-L83)) — the existing 6-enum field (`debt|housing|family|career|retirement|taxes`). NOT the 18 `life_event_*` routing tokens in `_route_intents_generated.py:74-86` and NOT a new schema field.
  - **D-01 supersession (2026-05-10, plan-revision iteration 1):** The bundle compiler reads `_classify_user_intent(message)` ([coach_chat.py:944-963](services/backend/app/api/v1/endpoints/coach_chat.py#L944-L963)) — the always-on heuristic returning the same 6-enum `set[str]`. Decouples Phase 93.5 from `COACH_DUAL_LLM_ENABLED` (Phase 91 flag), is already calculated unconditionally at coach_chat.py:2804 (`detected_intents`), runs in <1ms (vs 2-10s LLM extractor call), and `narrator_eval_50.jsonl` already exercises it. Per RESEARCH §3.2 + §A1 + Anti-pattern 4 + Pitfall 5. The 6-enum value space is identical between paths — no semantic drift. `ExtractorOutput.intents` remains a valid future fallback if Phase 97+ introduces ML-based routing.
- **D-02:** Static intent → bundle mapping (v1):
  - `retirement` → `{pillar3a-optimizer, lpp-projector}`
  - `taxes` → `{tax-explainer, pillar3a-optimizer}` (3a is a tax deduction lever)
  - `housing` → `{mortgage-stressor, tax-explainer}` (housing has tax implications)
  - `debt` → `{mortgage-stressor, compliance-narrator}` (debt → safe-mode is compliance-critical)
  - `family` → `{life-event-router, compliance-narrator}` (family events trigger life-event routing)
  - `career` → `{lpp-projector, life-event-router}` (career change = LPP transitions)
- **D-03:** Spec drift acknowledgement: ROADMAP.md success criterion #2 says "from extractor's life_event field" — that field does not exist in current extractor. CONTEXT supersedes: compiler reads `intents`, not `life_event`. ROADMAP wording will be patched in Phase 93.5 plan-01 to match D-01.
- **D-04:** No resolver layer in v1 (Karpathy #2 Simplicity First). The static mapping IS the resolver. If post-launch logs show mis-routing >2%, a smarter resolver becomes Phase 97+.

### Bundle Module Format (Gray Area B)

- **D-05:** Pure Python module per bundle, exposing a Pydantic v2 `BaseModel` with frozen config:
  ```python
  # services/backend/app/services/coach/bundles/pillar3a_optimizer.py
  class Pillar3aOptimizerBundle(BundleBase):
      name: Literal["pillar3a-optimizer"] = "pillar3a-optimizer"
      prompt_fragment: str = """..."""
      allowed_tools: list[str] = [...]
      citation_allowlist: list[str] = [...]
  ```
- **D-06:** Reject YAML+Markdown (Anthropic's format). MINT's stack is Pydantic v2 + FastAPI, not Managed Agents API. Pure Python gives type-checking, IDE jump-to-def, mypy/ruff, unit testability, and `grep -rn "garanti"` audit-friendliness for free.
- **D-07:** Reject hybrid (Python + sibling .md files). Half-measure that pays both costs.
- **D-08:** Shared base class `BundleBase(BaseModel)` in `bundles/__init__.py` with `model_config = ConfigDict(frozen=True, extra="forbid")` to enforce the contract.

### Composition + Always-On Rules (Gray Area C)

- **D-09:** Always-on bundles (every request, regardless of intents):
  - `compliance-narrator` — banned terms, accents, archetype detection, LSFin doctrine. Defense-in-depth, never skipped.
  - `life-event-router` — 18-event catalog small enough (~600 tokens) to keep always-on, ensures generic routing semantics survive.
- **D-10:** Intent-driven bundles (activated per D-02 mapping): `pillar3a-optimizer`, `lpp-projector`, `tax-explainer`, `mortgage-stressor`.
- **D-11:** Compiler output structure: `final_prompt = ALWAYS_ON_FRAGMENTS + DEDUPED_INTENT_FRAGMENTS`, in that order. Always-on first ensures compliance/routing rules are read before domain content.
- **D-12:** Multi-bundle dedup rules:
  - `citation_allowlist` is union'd across activated bundles (no duplicates in final list)
  - `allowed_tools` is union'd across activated bundles
  - `prompt_fragment` strings are concatenated with `\n\n---\n\n` separator (no string-level dedup; bundle authors own non-overlap)
- **D-13:** Token budget enforcement: hard cap 8k tokens (success criterion #3). If `len(final_prompt_tokens) > 8000`, compiler drops lowest-priority intent bundle in this order: `mortgage-stressor` → `tax-explainer` → `lpp-projector` → `pillar3a-optimizer`. Always-on bundles (compliance-narrator, life-event-router) NEVER dropped.
- **D-14:** Empty-intent path: when `intents == []` (e.g. user says "merci"), compiler emits ONLY always-on bundles (~1.5k tokens, 4-5× lighter than legacy prompt).

### Migration + Feature Flag (Gray Area D)

- **D-15:** Feature flag `COACH_BUNDLE_COMPILER_ENABLED` (env var), default `false` in prod, `true` in staging during Stage 3 eval. Mirrors Phase 91's `COACH_DUAL_LLM_ENABLED` pattern ([91-CONTEXT.md](.planning/phases/91-mvp-extractor-v2/91-CONTEXT.md) precedent).
- **D-16:** Two prompt-builder paths preserved during rollout:
  - Legacy: `build_narrator_system_prompt()` ([claude_coach_service.py:895](services/backend/app/services/coach/claude_coach_service.py#L895)) — unchanged
  - New: `build_narrator_system_prompt_from_bundles(*, intents, ctx, language, cash_level)` — bundle-compiler path. Kwargs-only signature mirroring `_build_prompt`. Memory blocks (`commitment_block`, `intelligence_block`, `insight_block`) are concatenated POST-prompt at coach_chat.py:766–781, IDENTICAL to the legacy flow — they are NOT parameters of `build_narrator_system_prompt_from_bundles`.
  - `coach_chat.py` selects path via flag at request time
- **D-17:** Migration is incremental, NOT big-bang. Wave plan:
  1. Wave 0 (Plan 93.5-01): scaffold 6 bundle modules with thin stubs (compliance-narrator + life-event-router copy fragments verbatim from legacy prompt; 4 domain bundles start with ~200-token doctrine-only fragments).
  2. Wave 1 (Plan 93.5-02): bundle_compiler.py + flag wiring + dual-path coach_chat.
  3. Wave 2 (Plan 93.5-03): incrementally fatten domain bundle fragments based on what Stage 3 eval shows matters.
  4. Wave 3 (Plan 93.5-04): 50-fixture eval pack on bundle path; cost+latency telemetry on staging; flag flip-on plan.
- **D-18:** Phase 94 hard-dependency: `citation_allowlist` consumed by citation-gate IF flag-on, else falls back to a global registry (graceful degradation). Phase 94 plan must check the flag.
- **D-19:** Sunset plan: remove flag + delete `_NARRATOR_BASE_SYSTEM_PROMPT` in Phase 95 once Stage 3 eval pack passes ≥95% on bundle path. Until then, both paths coexist. Wave 3 (Plan 93.5-04) annotates `_NARRATOR_BASE_SYSTEM_PROMPT` with a deprecation marker comment + import-time `DeprecationWarning` (when the flag is ON) — this satisfies BUNDLE-04 « deprecation » without violating D-19's deletion deferral.

### Tool Registry Mapping (Gray Area E — locked plan-revision iteration 1, 2026-05-10)

- **D-20 (locked 2026-05-10):** Bundle `allowed_tools` MUST reference only names from the verified narrator-tool registry at `services/backend/app/services/coach/coach_tools.py:637-730`. The 6 real tools are : `get_budget_status` (637), `get_retirement_projection` (653), `get_cross_pillar_analysis` (669), `get_cap_status` (685), `get_couple_optimization` (701), `get_regulatory_constant` (722). Any other name is invented and fails `test_bundle_allowed_tools_subset_of_narrator_registry`. Mapping :
  - `compliance-narrator` → `[]` (doctrine-only, no tool calls)
  - `life-event-router` → `["get_budget_status", "get_retirement_projection"]`
  - `pillar3a-optimizer` → `["get_retirement_projection", "get_cross_pillar_analysis"]`
  - `lpp-projector` → `["get_retirement_projection", "get_cross_pillar_analysis"]`
  - `tax-explainer` → `["get_regulatory_constant", "get_cross_pillar_analysis"]`
  - `mortgage-stressor` → `["get_budget_status", "get_cap_status", "get_regulatory_constant"]`

### Reusable Assets
- **Pydantic v2 BaseModel + frozen config**: precedent in [extractor_schema.py:103](services/backend/app/services/coach/extractor_schema.py#L103) (`{"extra": "forbid", "frozen": True}`) — reuse identically in `BundleBase`.

- **`_build_prompt`**: [claude_coach_service.py:754](services/backend/app/services/coach/claude_coach_service.py#L754) shared assembly for legacy + narrator paths; bundle path adds a 3rd path that takes pre-composed bundles instead of `base_template`. Signature is kwargs-only `(*, base_template, ctx, language, cash_level)` and provides ALL 7 slots unconditionally.
- **`CoachContext`**: passed into prompt builders today; bundle compiler keeps the same signature (`ctx`, `language`, `cash_level`) plus new `intents: set[str]` (heuristic path per D-01 supersession).
- **`COACH_DUAL_LLM_ENABLED` flag pattern**: Phase 91 precedent for env-var-gated rollout — copy approach.
- **Banned-terms reminder**: `_BANNED_TERMS_REMINDER` constant injected into prompt; compliance-narrator bundle owns this fragment.
- **Regional + lifecycle blocks**: 11 appended blocks in `_build_prompt` (life-event catalog, archetype catalog, doctrine, voice, anti-patterns, biography, commitment, intelligence, couple, language, user context). The bundle compiler reuses the same appended blocks (NO change to `_build_prompt`'s post-base composition); only `base_template` is replaced by composed bundle fragments.

### Established Patterns
- **2-LLM coach loop** (extractor → narrator) is the runtime contract; bundle compiler operates entirely within the narrator path's prompt-build step. No change to the loop topology.
- **Format-string slot pattern**: `_build_prompt` calls `base_template.format(banned_terms, regional_identity, lifecycle_awareness, plan_awareness, check_in_protocol, safe_mode_protocol, routing_rules)` — exactly 7 slots, all provided unconditionally. Bundle fragments MUST use only these 7 slot names. Compiler MUST scan the assembled prompt and reject any 8th undeclared slot before returning (raises `ValueError`).
- **Phase 91 invariant test pattern**: `tests/test_extractor_schema.py::test_canonical_keys_mirror_coach_chat` ensures schema and consumer stay in sync. Mirror this with `tests/test_bundles/test_bundle_contract.py::test_bundle_citation_allowlist_subset_of_grounding_pack` (citation keys MUST be subset of GroundingPack registry).

### Integration Points
- **Bundle compiler entrypoint**: `bundle_compiler.py:compile_bundles(intents, ctx, language) -> CompiledBundle` returning `(prompt: str, allowed_tools: list[str], citation_allowlist: list[str])`.
- **`coach_chat.py` request handler**: `_run_extractor_stage` → reads `intents` (from `_classify_user_intent` per D-01 supersession) → branches on `COACH_BUNDLE_COMPILER_ENABLED` → `compile_bundles()` → `_run_agent_loop` with filtered tool list.
- **Phase 94 citation-gate**: reads `compiled.citation_allowlist` (when flag-on) instead of a global allowlist; gates narrator output regex match against this list.
- **Phase 95 DAG-invalidation**: `inputs_hash` propagation to `citation_allowlist` keys ensures stale citations get rejected. No change in 93.5; 95 will read 93.5's allowlist contract.

<specifics>
## Specific Ideas

- **Audit Proposal A is the design spec**, not a suggestion. Read it cover-to-cover before writing code.
- **Bundle naming uses underscores in Python module names** (`pillar3a_optimizer.py`) but **kebab-case in `name` field** (`pillar3a-optimizer`) — matches Anthropic financial-services convention and ROADMAP wording.
- **Compliance-narrator bundle is the contract anchor**: its `prompt_fragment` is the most heavily reviewed (LSFin compliance gate). Treat as ADR-equivalent — every change requires panel review per `feedback_design_panel_before_push.md`.
- **Life-event-router bundle is the lightest** but spans the 18-event taxonomy. Keep fragment ≤600 tokens; deeper per-event routing logic stays in the (existing) extractor + intent classifier, not in the bundle.
- **Citation allowlist keys MUST be drawn from the calc-first ADR's GroundingPack registry** — bundles cannot invent citation keys. Until Phase 95 populates the registry, every key carries an inline `# TODO Phase 95 — pending GroundingPack registry` comment for traceability ; `test_bundle_citation_allowlist_subset_of_grounding_pack` remains xfail.

</specifics>
