## Summary

Phase 93.5 introduit une **couche de composition compile-time** entre les 7 « slots » du prompt narrateur monolithique et l'appel LLM. 6 bundles Pydantic v2 frozen (`compliance-narrator`, `life-event-router` toujours-on ; `pillar3a-optimizer`, `lpp-projector`, `tax-explainer`, `mortgage-stressor` activés par `intents`) déclarent chacun `prompt_fragment`, `allowed_tools`, `citation_allowlist`. Un `bundle_compiler.py` lit `ExtractorOutput.intents` (déjà disponible — voir D-01 + §1.3 ci-dessous) et compose une seule chaîne narrateur + une liste de tools filtrée + une liste de citations.

Trois corrections empiriques s'imposent par rapport au CONTEXT.md :

1. **« 30k tokens » est une erreur d'unité** — le prompt narrateur final fait actuellement **~30 412 chars / ~7 603 tokens** (estimation 4 char/token), pas 30k tokens. Le template `_NARRATOR_BASE_SYSTEM_PROMPT` lui-même fait ~1 950 tokens ; les 5 650 autres tokens viennent des 11 blocs appendus dans `_build_prompt`. Le budget cible 8k est donc **à peine en-dessous** du baseline actuel — la −40% cost regression est atteignable seulement par dropping intelligent + refactor du `LIFE_EVENT_CATALOG` always-on.
2. **Il y a 7 slots format-string, pas 6** — `_NARRATOR_BASE_SYSTEM_PROMPT` expose `banned_terms`, `regional_identity`, `lifecycle_awareness`, `plan_awareness`, `check_in_protocol`, `safe_mode_protocol`, `routing_rules`. Voir §3 slot-table.
3. **Le signal `intents` existe déjà au runtime via deux paths** : `ExtractorOutput.intents` (Phase 91, list[Literal] max 4, derrière `COACH_DUAL_LLM_ENABLED`) ET `_classify_user_intent(message)` (heuristique keyword-based, Phase 90.x B14, `set[str]`, **toujours actif** indépendamment du flag). Les deux utilisent le même 6-enum. Voir §3.2.

**Primary recommendation :** scaffolder les 6 bundles + base class avec **fragments verbatim copiés depuis les blocs existants** dans Wave 0 (zéro behavior change), puis wirer le compileur derrière `COACH_BUNDLE_COMPILER_ENABLED` en utilisant le signal `_classify_user_intent` (déjà calculé à coach_chat.py:2804) — le path n'a aucune dépendance sur Phase 91's flag, ce qui découple Phase 93.5 du Stage 4 dual-LLM rollout.

### 3.2 Pattern 1 : Bundle Activation Signal (CRITICAL — résout open-question #1)

**Source signal candidat :** `intents` champ de `ExtractorOutput` (Phase 91, list[Literal] max 4).

**Découverte importante** : il existe **DEUX path runtime** qui produisent ce signal aujourd'hui.

| Path | Localisation | Trigger | Type |
|------|--------------|---------|------|
| **Heuristique keyword** (toujours actif) | `coach_chat.py:944 _classify_user_intent` (B14, 2026-05-09) | Sur **chaque turn**, indépendamment des feature flags | `set[str]` (même 6-enum) |

3. **Symétrie eval** — le pack `narrator_eval_50.jsonl` ne contient pas de `intents` field ; les fixtures déclenchent uniquement la heuristique. Tester le bundle path avec la heuristique = parité directe avec le narrateur baseline.

### Anti-Patterns to Avoid

- **Anti-pattern 1 : Re-implementing calculation logic inside a bundle's `prompt_fragment`** — CLAUDE.md §1 forbids this. The fragment cites tools (`get_retirement_projection`, etc.), it does NOT inline numbers. The `{{cite:<key>}}` placeholder syntax is the contract per ADR `2026-05-09-calc-first-llm-illumination.md` N1.
- **Anti-pattern 2 : Adding a runtime resolver layer** — CONTEXT D-04 forbids this in v1. The static `_INTENT_BUNDLES` dict IS the resolver. If post-launch logs show >2% mis-routing, it becomes Phase 97+.
- **Anti-pattern 3 : Hot-reload of bundle modules** — CONTEXT deferred. Bundles are imported at FastAPI start ; restart required for prompt changes.
- **Anti-pattern 4 : Reading `ExtractorOutput.intents` (Phase 91 LLM extractor) instead of `_classify_user_intent` (heuristic)** — couples Phase 93.5 to `COACH_DUAL_LLM_ENABLED` and to LLM extractor latency. See §3.2. **Recommend lifting D-01 in plan 93.5-01.**
- **Anti-pattern 5 : Over-engineering `BundleBase` with abstract methods, `__init_subclass__` hooks, registry decorators** — Karpathy #2 Simplicity First. The 6 bundles are imported by name in `bundle_compiler.py` ; no metaclass magic needed.
- **Anti-pattern 6 : Splitting `_build_prompt`'s 11 appendix blocks across bundles** — leave the appended blocks (lifecycle, archetype, etc.) where they are; bundles only replace the `base_template`. CONTEXT §code_context line 153 says explicitly « only `base_template` is replaced ».
- **Anti-pattern 7 : Using `tiktoken` for the 8k token budget enforcement** — `tiktoken` is OpenAI's encoder and undercounts French accented prompts vs Anthropic's actual tokenizer by 5-15%. Use `client.messages.count_tokens` in CI / staging ; fallback to 4-char-per-token heuristic with 10% safety margin offline.

## Common Pitfalls

### Pitfall 1 : Slot-string interpolation drift

**What goes wrong :** un bundle's `prompt_fragment` contient un `{slot}` non-déclaré (e.g. l'auteur copie `{routing_rules}` depuis `_TOOL_ROUTING_RULES` dans `compliance-narrator` mais le compileur ne sait pas que ce slot doit être interpolé).

**Why it happens :** la copie verbatim du legacy block conserve les format-strings ; `str.format()` lève `KeyError` au runtime sur le premier appel narrateur après merge.

**How to avoid :** au compile-time, scanner chaque `prompt_fragment` pour les slots avec `re.findall(r"\{(\w+)\}", fragment)` ; rejecter si un slot non-déclaré est présent. Test :

```python
def test_bundle_no_undeclared_slots():
    declared = {"banned_terms", "regional_identity", "lifecycle_awareness",
                "plan_awareness", "check_in_protocol", "safe_mode_protocol",
                "routing_rules"}
    for bundle in ALL_BUNDLES:
        slots = set(re.findall(r"\{(\w+)\}", bundle().prompt_fragment))
        undeclared = slots - declared
        assert not undeclared, f"{bundle.__name__} has undeclared slots: {undeclared}"
```

**Warning signs :** `KeyError` in production logs at the `_build_prompt` `.format(...)` call (line 789). Run the test BEFORE merging.

### Pitfall 2 : Token-count drift between estimation and Anthropic billing

**What goes wrong :** the 4-char-per-token heuristic underestimates by 8-12% on FR-with-accents (each `é` is 2 UTF-8 bytes but ~1 token in Claude's BPE). A bundle stack that estimates at 7'800 tokens may bill at 8'600 in production.

**Why it happens :** different tokenizers count differently ; tiktoken (GPT) is biased low for FR ; the heuristic is ~stable but wrong direction.

**How to avoid :**
- In CI : use `len(s) // 4` with a hard cap of `_TOKEN_BUDGET * 0.90 = 7'200` (10% safety margin).
- On staging : call `client.messages.count_tokens(model="claude-sonnet-4-5-20250929", system=compiled.prompt, messages=[{"role":"user","content":"."}])` once per fixture during eval. Cache result keyed by `sha256(prompt)`.
- In prod : trust the heuristic ; reconcile against Sentry breadcrumb `coach.bundle.prompt_tokens` vs Anthropic billing weekly.

**Warning signs :** Sentry `coach.bundle.prompt_tokens` vs Anthropic API `usage.input_tokens` divergence > 15% on the same prompt. Recalibrate margin.

### Pitfall 3 : Always-on bundle drops on 8k overflow

**What goes wrong :** the planner inadvertently lets `compliance-narrator` or `life-event-router` enter the drop priority list. A turn with `{retirement, taxes, housing}` at full fragment size could exceed 8k ; under naive drop logic, compliance might be the casualty. **Compliance dropping = LSFin violation = mort de marque.**

**Why it happens :** mis-coded `_DROP_PRIORITY` or off-by-one on the always-on guard.

**How to avoid :** explicit Pydantic-typed list `_DROP_PRIORITY: list[type[BundleBase]]` + invariant test :

```python
def test_drop_priority_never_includes_always_on():
    from app.services.coach.bundle_compiler import _DROP_PRIORITY, _ALWAYS_ON
    assert set(_DROP_PRIORITY) & set(_ALWAYS_ON) == set(), (
        "DROP_PRIORITY contains an always-on bundle — would violate D-13"
    )
```

**Warning signs :** Sentry breadcrumb `coach.bundle.activated` missing `compliance-narrator` or `life-event-router` on any turn. Alert at any occurrence.

### Pitfall 4 : Fragment overlap creates contradictory doctrine

**What goes wrong :** `compliance-narrator` says « always quote a CHF amount » ; `mortgage-stressor` says « never quote a CHF without LTV context ». Concatenated `\n\n---\n\n`, the LLM sees both. Conflict resolution falls back to LLM heuristic = unpredictable.

**Why it happens :** D-12 explicitly says no string-level dedup ; bundle authors own non-overlap. Without a review gate, drift accumulates.

**How to avoid :** treat `compliance-narrator.prompt_fragment` as the authoritative doctrine layer ; domain bundles MAY add specifics but MUST NOT contradict. Per CONTEXT specifics line 171 : « Compliance-narrator bundle is the contract anchor : its prompt_fragment is the most heavily reviewed (LSFin compliance gate) ». Add a `panel_review_required: bool = True` marker on `ComplianceNarratorBundle` (deferred to discuss-phase if controversial).

**Warning signs :** post-merge eval pack score on `lsfin` category drops below baseline. The 13-fixture LSFin slice in `narrator_eval_50.jsonl` is the canary.

### Pitfall 5 : `_classify_user_intent` heuristic vs `ExtractorOutput.intents` divergence

**What goes wrong :** when both `COACH_BUNDLE_COMPILER_ENABLED` and `COACH_DUAL_LLM_ENABLED` are ON, two intent signals exist on the same turn :
- `_classify_user_intent(message)` → keyword-based set
- `ExtractorOutput.intents` → LLM-extracted list

If they disagree (e.g. message « j'ai 50k de dettes mais je veux acheter » : keyword path = `{debt, housing}` ; LLM might return only `["debt"]`), which one wins?

**Why it happens :** the two paths were designed independently in different phases.

**How to avoid :** plan 93.5-02 LOCKS the choice. Recommended : keyword path (Anti-pattern 4 above). If Julien locks LLM path, the compileur must check `COACH_DUAL_LLM_ENABLED` and fallback to keyword on flag-OFF.

**Warning signs :** Stage 3 eval pack output bundles list differs between two consecutive runs of the same fixture (LLM extractor non-determinism). Pin the choice via test.

### Pitfall 6 : Empty-intent path skips compliance

**What goes wrong :** misreading D-14 (« empty intents → only always-on bundles ») as « empty intents → empty bundles ».

**Why it happens :** « only » vs « no ».

**How to avoid :** explicit test :

```python
def test_empty_intent_path_emits_always_on():
    compiled = compile_bundles(intents=set(), ctx=None)
    assert "compliance-narrator" in compiled.activated_bundles
    assert "life-event-router" in compiled.activated_bundles
    assert compiled.estimated_tokens > 1_000  # not empty
```

**Warning signs :** « merci » turn produces empty narrator prompt → narrator hallucinates without any doctrine guard. Catastrophic on first turn.

### Pitfall 7 : `BundleBase` mutation via `model_copy`

**What goes wrong :** Pydantic v2 `frozen=True` prevents `bundle.allowed_tools.append(...)`, but NOT `bundle.model_copy(update={"allowed_tools": [...]})`. A test or downstream code that calls `model_copy` to "extend" tools breaks the contract.

**Why it happens :** `frozen` only blocks direct attribute mutation. `model_copy` is intentional escape hatch.

**How to avoid :** the compiler does NOT mutate bundles ; it reads `.allowed_tools`, `.citation_allowlist`, `.prompt_fragment` and unions them in fresh local lists. Test :

```python
def test_bundle_instances_are_immutable_via_attribute():
    bundle = ComplianceNarratorBundle()
    with pytest.raises(ValidationError):
        bundle.allowed_tools = ["foo"]  # frozen blocks this
```

**Warning signs :** N/A (would be caught at first integration test if violated).

### Pitfall 8 : `count_tokens` API rate-limit during CI

**What goes wrong :** running the full 50-fixture eval pack with `count_tokens` per fixture × 6 intent combinations = ~300 API calls per CI run. At Anthropic's tier-1 rate limit (50 RPM `count_tokens`), CI takes 6+ minutes just for tokenization.

**Why it happens :** no caching ; CI re-tokenizes identical compiled prompts every run.

**How to avoid :** cache `count_tokens` results by `sha256(compiled.prompt)` in `tests/fixtures/.token_count_cache.json` (committed). Invalidate when the bundle modules change (hash bundles' `__file__` mtimes). Local dev / CI : if cache hit, skip the API call.

**Warning signs :** CI duration on `tests/bundles/` job > 5 min.

### Example 2 : `bundle_compiler.compile_bundles` core logic

```python
def compile_bundles(
    intents: set[str],
    ctx: Optional[CoachContext] = None,
    language: str = "fr",
) -> CompiledBundle:
    # Step 1: collect bundle classes per D-09 + D-10.
    bundle_classes: list[type[BundleBase]] = list(_ALWAYS_ON)
    seen: set[type[BundleBase]] = set(_ALWAYS_ON)
    for intent in sorted(intents):  # sorted for determinism
        for cls in _INTENT_BUNDLES.get(intent, []):
            if cls not in seen:
                bundle_classes.append(cls)
                seen.add(cls)

    # Step 2: instantiate (Pydantic frozen — no kwargs needed for stub).
    activated: list[BundleBase] = [cls() for cls in bundle_classes]

    # Step 3: assemble candidate prompt.
    def _assemble(bundles: list[BundleBase]) -> tuple[str, int]:
        fragments = [b.prompt_fragment for b in bundles]
        prompt_str = "\n\n---\n\n".join(fragments)
        return prompt_str, len(prompt_str) // 4  # heuristic; reconcile in CI

    prompt, est_tokens = _assemble(activated)

    # Step 4: drop right-to-left if over budget (D-13).
    dropped: list[str] = []
    while est_tokens > _TOKEN_BUDGET and any(
        cls in _DROP_PRIORITY for cls in [type(b) for b in activated]
    ):
        for drop_cls in _DROP_PRIORITY:
            in_activated = [b for b in activated if isinstance(b, drop_cls)]
            if in_activated:
                activated = [b for b in activated if not isinstance(b, drop_cls)]
                dropped.append(drop_cls.__name__)
                break
        prompt, est_tokens = _assemble(activated)

    # Step 5: dedup tools + citations (D-12).
    allowed_tools = sorted({t for b in activated for t in b.allowed_tools})
    citation_allowlist = sorted({c for b in activated for c in b.citation_allowlist})

    return CompiledBundle(
        prompt=prompt,
        allowed_tools=allowed_tools,
        citation_allowlist=citation_allowlist,
        activated_bundles=[b.name for b in activated],
        estimated_tokens=est_tokens,
    )
```

### Known Threat Patterns for FastAPI / Pydantic / LLM-prompt-build stack

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Prompt-injection via slot interpolation (`{...}`) escaping format-string boundaries | Tampering | `_INJECTION_PATTERNS` filter at coach_chat.py:2797 (existing) ; bundle compiler does NOT re-interpolate slots from user input — slots are interpolated from `ctx` and `_BANNED_TERMS_REMINDER` only |
| Pydantic `model_config` mismatch leading to silent attribute drift | Tampering | `extra="forbid"` rejects unknown fields ; `frozen=True` blocks mutation ; invariant test at import time |
| Telemetry leaking user message content via Sentry breadcrumb | Information Disclosure | Breadcrumb payload limited to `(activated_bundles: list[str], prompt_tokens: int)` — no message content |
| Bundle import-time exception kills FastAPI worker | DoS | Pydantic `BaseModel` validation happens at class definition (not first instance) → caught by import-time test ; if a bundle module raises on import, CI fails before deploy |
| Citation key leak via `citation_allowlist` (e.g. `user_avs_rente_low` reveals computation path) | Information Disclosure | `citation_allowlist` is server-side only ; never serialized to user-facing response. Phase 94 citation-gate substitutes the placeholder with the value, then `{{cite:<key>}}` is never seen by the user. |
