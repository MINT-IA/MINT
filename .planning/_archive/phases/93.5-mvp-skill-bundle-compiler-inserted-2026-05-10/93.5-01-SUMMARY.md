- **D-01 supersession encoded statically.** PLAN frontmatter carries `decision_lock=D-01-superseded-to-classify_user_intent` ; CONTEXT D-01 documents the supersession verbatim. No runtime checkpoint required ; the bundle compiler in Plan 93.5-02 will consume `intents: set[str]` from `_classify_user_intent` (heuristic, always-on, coach_chat.py:944), NOT `ExtractorOutput.intents`. Marking `strict=True` would have forced an immediate failure when keys arrive — the chosen non-strict xfail is the lower-friction Phase 95 handoff.
- **`CoachContext` is a `@dataclass`, not Pydantic.** The plan's `_load.py` example used Pydantic-style kwargs ; the actual class (coach_models.py:46-90) is a `@dataclass` with field defaults. `_load.py` was rewritten to pass only the fields that materially affect prompt output (`archetype`, `canton`, `age`, `has_debt`) and treat `language` + `cash_level` as separate `build_narrator_system_prompt` arguments (they are NOT CoachContext fields).

- **Issue:** Plan acceptance said `grep "llm-doctrine-fragment-banned-list" compliance_narrator.py` should return **1** match.
