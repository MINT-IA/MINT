# UI drift baseline — 2026-05-09 (Phase MVP-DESIGN-LINTS-V1)

Total: 1036 grandfathered violations across 5 design lints.
Net-new violations BLOCK CI (`.github/workflows/design-lints.yml`).
Existing violations are deferred to Phase 3 (FONTS-TOKENS-V2) + Phase 4
(CTA-UNIFICATION-V1) sweep PRs.

How baselines work:
  - Each `tools/checks/prefer_mint_*.baseline.txt` is a sorted list of
    `path:line: snippet` rows.
  - The lint passes when current_violations is a subset of baseline.
  - Net-new violations fail with exit 1.
  - Run `python3 tools/checks/<lint>.py --update-baseline` after a sweep
    PR to shrink the baseline (always a separate, reviewed commit).

## Counter-arguments and data gaps

- **Counter-argument**: « 1036 grandfathered entries is a quarter of the
  drift budget. The lint catches new violations only — it doesn't shrink
  the existing surface. » Rejected: this is the milestone strategy
  (RESEARCH §Locked Decisions). Phases 3 + 4 do the sweeping; Phase 1
  stops the bleeding. Without Phase 1, every Phase 3/4 sweep PR risks
  re-introducing the violations being swept.

- **Data gap**: empirical false-positive rate is unmeasured. Synthetic
  fixtures in `tools/checks/tests/fixtures/` cover the canonical RED/
  GREEN cases; real-world FP rate (regex over multi-line TextStyle blocks,
  comment-stripped doc lines) becomes visible only on the first 3 PRs
  that touch `apps/mobile/lib/**/*.dart`. Track in VERIFICATION.md at
  phase close. PLAN-CHECK §3 R4 promotes this to a follow-up perimeter
  if FP > 10% on any lint.

- **Data gap**: lefthook latency on a 100-file commit (sweep PR shape)
  is unmeasured. Budget is ≤ 1.5 s on a 1-line commit; 100-file commits
  may exceed this. Mitigation in plan §Risks (fold into a single
  dispatcher script) is deferred until empirically required.
