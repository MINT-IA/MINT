# Phase 01.4 — Coach-runtime stale-data + forced tool-invocation

> Carries sub-phase 01.1's P1 + P2 findings (F-01.1-02 / F-01.1-05 / F-01.1-06) + the « 25 fois tentées » regression class around coach hallucinating Swiss regulatory constants instead of invoking the registry tool. Single audit doc, no intermediate ceremony (per Phase 01.1 lessons-learned § lean process).

## 1. Root cause (proven 2026-05-21 inline grep + curl probes)

**The « 25 fois » mystery resolves as 2 distinct architectural bugs :**

### Bug 1 — Anonymous coach path has NO TOOLS wired

[`services/backend/app/api/v1/endpoints/anonymous_chat.py:173`](services/backend/app/api/v1/endpoints/anonymous_chat.py#L173) passes **`tools=None`** to `LLMClient.generate()`. The Anthropic LLM has zero tool definitions → no path to call `get_regulatory_constant` → no choice but to answer from training-data → cites 7'056 (cycle 2023-2024 known to Claude) instead of 7'258 (registry serves it but the LLM can't reach it).

**Evidence :**
```python
# services/backend/app/api/v1/endpoints/anonymous_chat.py:169-174
raw_response = await llm_client.generate(
    system_prompt=system_prompt,
    user_message=question,
    context_chunks=[],
    tools=None,                # ← THE BUG
)
```

### Bug 2 — Mistaken tool name in doctrine

`CLAUDE.md` §3 + memory `project_coach_forced_tool_invocation` refer to **`get_swiss_constants(category)`** as the canonical tool. **That name does not exist in the backend.** It's an MCP tool local to Claude Code (developer-side, via `.mcp.json` mint-tools server) — NOT a runtime Anthropic tool registered for the production LLM.

The backend has **`get_regulatory_constant`** (singular) at [`services/backend/app/services/coach/coach_tools.py:737`](services/backend/app/services/coach/coach_tools.py#L737) — but only the authenticated coach path ([`coach_chat.py:88+186`](services/backend/app/api/v1/endpoints/coach_chat.py#L88)) wires it.

**Memory + doctrine reference the wrong tool name** → every fix that « added forced tool-invocation » targeted a tool that doesn't exist in the runtime → 25 fix attempts touched system prompts and gates but never the missing `tools=` parameter.

## 3. Fix — defense-in-depth 4 couches dans 1 PR

**Surgical patch, scoped to `anonymous_chat.py` + new helper.** Ne touche pas la coach pipeline authentifiée (déjà câblée).

### Couche A — Pass tools=[get_regulatory_constant] au LLM

```python
# anonymous_chat.py
from app.services.coach.coach_tools import get_llm_tools
# Filter to just the regulatory-constant tool (anonymous = no profile data)
_anon_tools = [t for t in get_llm_tools() if t["name"] == "get_regulatory_constant"]

raw_response = await llm_client.generate(
    ...
    tools=_anon_tools,         # ← FIX
)
```

### Couche B — 1-iteration tool-use agent loop

Le LLM peut retourner :
- `text` direct → utilise tel quel
- `tool_use` block (call `get_regulatory_constant`) → exécute le tool (call staging endpoint), renvoie `tool_result` au LLM, récupère le `text` final
- Mixed (text + tool_use) → idem, finalize avec tool_result

Loop max 1 itération pour rester dans le budget anonymous (3-msg/session, <30s timeout).

### Couche C — Forced tool_choice sur détection finance-keyword

Si user message contient `\b(3a|3eme|3ème|lpp|avs|plafond|rente|cotisation|fiscal|impôt|fortune|salaire|taux)\b` :
```python
# In LLMClient.generate or in the anonymous handler
kwargs["tool_choice"] = {"type": "tool", "name": "get_regulatory_constant"}
```

Force la première action = appel outil.

### Couche D — Post-response halucination gate (use existing `runtime_freshness_gate.py`)

Le module `services/backend/app/services/coach/runtime_freshness_gate.py` existe déjà (obs #157 Stage-3 quad-defense). Le brancher sur le path anonymous post-réponse. Si gate détecte un chiffre suspect ou un fact stale → REJECT + retry (1× max), sinon scripted fact-card.

## 7. Risk / counter-arguments

- **Risk : tool_use loop adds latency.** Mitigated : 1-iteration max, <2s per tool call vs current ~6s LLM-only response.
- **Risk : forced tool_choice on every finance-keyword spam = N× cost.** Mitigated : « 3-msg/session anonymous cap » already exists, plus regex is tight (only ~12 keywords).
- **Risk : freshness gate triggers false positives.** Mitigated : it's already tested in authenticated path, wave 1c-verified.
- **Counter-argument : « pourquoi pas juste utiliser /coach/chat authenticated avec un user anonyme ? »** — refactor scope much bigger, breaks anonymous rate-limit model, would need session-token plumbing. Lower-cost path is to add tools to existing anonymous endpoint.
