## Decisions Made

1. **Adopted dual declaration (ProfileBase + ProfileUpdate explicit) vs refactor to subclass.** The plan explicitly mandated this — ProfileUpdate is intentionally a `BaseModel` (not a ProfileBase subclass) so optional fields can be made non-required without changing ProfileBase contracts. Following the plan: same two fields declared explicitly in both.
2. **Adjusted Pydantic-int-coercion test from `usTaxPerson` to `nationality`.** The plan's Task 1 behavior spec Test 8 said "An invalid nationality (e.g. `{"nationality": 123}` int) raises `ValidationError`" — that's the correct spec for nationality. For `usTaxPerson`, the original test (`{"usTaxPerson": 1}` must raise) does NOT pass under Pydantic v2 default lax mode because `1` is coerced to `True` — documented Pydantic behavior, not a schema bug. R4 tri-state semantics target None vs False (proven by two separate dedicated tests), not int rejection. Replaced with a dict-rejection test that genuinely cannot coerce.
3. **PRIMARY OpenAPI regen path used; FALLBACK not invoked.** Diff was +75/-0, exactly the expected shape. No version skew, no exception, no unrelated drift.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] Test design: `usTaxPerson: 1` rejection test failed because Pydantic v2 default lax mode coerces 0/1 to bool.**
- **Found during:** Task 1 GREEN verification (`test_pydantic_us_tax_person_int_rejected` FAILED after schema edit)
- **Issue:** Test asserted `ValidationError` when validating `{"usTaxPerson": 1}` — but Pydantic v2 lax mode (which is the default and which the rest of the backend uses) coerces `1` → `True`. The result is still `True`, not `None`, so this is NOT an R4 tri-state violation. The original test design was overly strict and misaligned with the rest of the codebase's Pydantic posture.
- **Fix:** Replaced the test with two narrower tests aligned to the actual R4 contract: (a) `test_pydantic_nationality_int_rejected` — proves the genuinely-invalid case `{"nationality": 123}` IS rejected (this is the plan's Task 1 behavior Test 8 anyway); (b) `test_pydantic_us_tax_person_non_coercible_rejected` — proves a dict input (which cannot coerce to bool) IS rejected.
- **Files modified:** `services/backend/tests/test_profile_archetype_signal_roundtrip.py`
- **Verification:** 10/10 tests now pass; R4 tri-state guard (None != False) still proven by the dedicated `_null` / `_false` / `_default` tests.
- **Committed in:** `fde9e478` (Task 1 GREEN commit, same commit as the schema edit because both changes belong to a single TDD GREEN step).
