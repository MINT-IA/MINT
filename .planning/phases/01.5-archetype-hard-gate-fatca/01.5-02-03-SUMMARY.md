## Decisions Made

1. **OnboardingStep.usTaxPerson placement = T2.5 (between intents and age).** Security §4 (nLPD art. 6 minimization) requires the FATCA Q before any financial-data step (canton at T4, revenue at T5). Placing it at T2.5 keeps the storyboard's intent-first flow (user picks why they're here at T2) while still firing the gate before any salary / LPP / canton signal is captured. Alternative placements considered:
   - **T1 (pre-entry):** would force the question on every cold-open, even before the user knows what MINT is — bad UX.
   - **Post-T2 (where landed):** ✓ chosen — user has picked an intent, knows what's coming, FATCA Q feels relevant to MINT scope.
2. **CoachProfileProvider.mergeAnswers (not updateFromSmartFlow) is the write API.** `updateFromSmartFlow` requires age/grossSalary/canton (not yet collected at T2.5) and would corrupt the partial-profile flow. `mergeAnswers({'q_us_tax_person': bool})` is the minimal API that writes exactly one key + rebuilds `CoachProfile.fromWizardAnswers`.
3. **`clearAll()` is a NAMED ALIAS of `clear()`, not a new impl.** Both methods have identical semantics today (in-memory + `ReportPersistenceService.clear()` SharedPreferences wipe). The alias makes the call-site intent explicit (« clear all profile data on gate fire ») and gives us room to diverge later. The plan task 6 step 6.2 explicitly authorised either path (« If a clearAll method does NOT exist… add a minimal implementation »).
4. **Pure helper `evaluateCoachArchetypeGate(profile)` extracted from `coach_chat_screen.dart` gate site.** Decision logic is unit-tested without a widget tree (avoids the 2545-line screen's setup complexity). Trade-off: the integration (`context.go` + `WaitlistArgs` construction) is grep-verified rather than widget-tested. Acceptable per the plan acceptance criteria (Task 4 criterion #1 = `grep -n "context.go.*/waitlist"`).
5. **Refusal-marked placeholder CoachContext (archetype='unknown') paired with orchestrator-level guard.** When the route gate fires, `_buildCoachContext` queues `addPostFrameCallback(navigation)` AND returns a placeholder. The orchestrator-level `_calibratedArchetypes` guard at the top of `generateChat` then refuses the placeholder regardless. Defense-in-depth — no race window between the addPostFrameCallback firing and a synchronous chat send.
6. **WaitlistProvider.onGateSuccess callback is read off the route's BuildContext.** Reading `ctx.read<CoachProfileProvider>().clearAll()` at the `create:` callback keeps WaitlistProvider free of any direct dependency on CoachProfileProvider (no cyclic import). Verified by the 10/10 existing waitlist provider tests still passing (they pump WaitlistProvider in isolation without a CoachProfileProvider in the widget tree).
7. **MaterialLocalizations.of(ctx).okButtonLabel for the FATCA tooltip dialog dismiss button.** Flutter-provided + locale-aware, avoids hardcoding 'OK' AND avoids adding a 7th ARB key just for a single button label. Same value as the system-wide AlertDialog default.
8. **Storyboard test (mvp_wedge_storyboard_test.dart) _FakeCoachProfileProvider filters out the us-tax-person gate-only mergeAnswers call.** Preserves the existing `throwOnMerge` SnackBar test (which targets the T8 multi-key flush, not the T2.5 single-key gate write). Surgical: the filter is on `partial.length == 1 && partial.containsKey('q_us_tax_person')`, never matches a flush.

## Gate Flow Proof — end-to-end traced

A user opens MINT → taps « Ouvrir » (T1) → picks intent (T2) → answers « Oui » to « Es-tu citoyen ou résident fiscal aux États-Unis ? » (T2.5).

1. `UsTaxPersonScreen._answer(context, true)` → `CoachProfileProvider.mergeAnswers({'q_us_tax_person': true})`.
2. `CoachProfile.fromWizardAnswers({'q_us_tax_person': true})` → constructs a profile with `usTaxPerson: true`.
3. `CoachProfile.archetype` getter → FATCA short-circuit (`if (usTaxPerson == true) return FinancialArchetype.expatUs;` — plan 02-01 line 1905).
4. `OnboardingProvider.advance()` → step machine moves T2.5 → T3 (age). User answers age + canton + revenue normally → T7 → T8.
5. User taps « Creuser » at T8 → `OnboardingProvider.completeAndFlushToProfile(coachProvider)` → `coachProvider.mergeAnswers(...)` with all the dossier keys → profile gets `archetype == FinancialArchetype.expatUs`.
6. Storyboard navigates to `/coach/chat` → `_CoachChatScreenState` reads `_profile` from `CoachProfileProvider` (`didChangeDependencies`) → eventually calls `_buildCoachContext(profile)`.
7. **Task 4 gate fires:** `evaluateCoachArchetypeGate(profile)` returns `CoachArchetypeGateVerdict(shouldBlock: true, archetypeSlug: 'expat_us')` (since archetype != swissNative).
8. `addPostFrameCallback(() => context.go('/waitlist', extra: WaitlistArgs(archetype: 'expat_us')))` queued.
9. `_buildCoachContext` returns `CoachContext(archetype: 'unknown', ...)` placeholder.
10. If a chat send races with the postframe callback: `CoachOrchestrator.generateChat(ctx)` sees `ctx.archetype == 'unknown'` → **Task 5 guard fires** → returns `CoachResponse(refused: true, refusalReason: 'archetype_not_calibrated', message: 'MINT n\'est pas encore calibré pour ton profil...', disclaimer: ComplianceGuard.standardDisclaimer)`. LLM never invoked.
11. Postframe callback executes → `GoRouter` navigates to `/waitlist`.
12. `WaitlistScreen` renders → user enters email + checks consent box → taps CTA → `WaitlistProvider.submit(...)` → POST to backend → transitions to `WaitlistStatus.success` → `notifyListeners()`.
13. **Task 6 callback fires:** `onGateSuccess` invoked → `CoachProfileProvider.clearAll()` → `clear()` → SharedPreferences `wizard_answers_v2` key removed (nLPD art. 6 minimization, Security §6 Q5). No stale cached financial data bleeds across sessions.
14. WaitlistSuccess screen renders with the « Merci, on revient vers toi… » message + « Revenir à l'accueil » CTA → user taps → router goes to '/'.

Counter-flow: a swissNative user (nationality=CH, isCouple irrelevant) answers « Non » at T2.5 → archetype = swissNative → `evaluateCoachArchetypeGate(profile).shouldBlock == false` → coach context built normally → LLM proceeds.
