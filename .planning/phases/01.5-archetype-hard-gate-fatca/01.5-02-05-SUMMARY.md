## Decisions Made

1. **Flag-only migration is the Codex C1 HIGH structural fix.** The previous draft of this plan injected a Swiss nationality default to legacy null-nationality profiles. That is data-truth corruption — exactly the bug-class sub-phase 01.5 is built to close. Instead, the migration sets a SharedPreferences flag and the OnboardingShellScreen FutureBuilder consults the flag BEFORE constructing the step-machine provider. The legacy ambiguous profile is routed to the US-tax-person Q step BEFORE archetype detection runs, so the «all signals null → unknown» branch never fires until the user has supplied a fresh signal. The data-truth boundary holds.

2. **Pre-archetype guard via FutureBuilder + named constructor** rather than a redirect-style route handler. Rationale: the redirect-style approach would have required a new GoRouter handler that consults the flag and rewrites the destination — more surface area, more places to forget the check. The FutureBuilder is co-located with the screen that owns the step machine, so the contract is grep-discoverable from one file. Karpathy #2 (Simplicity First) — 33 lines added vs ~80 lines for a redirect handler with its own tests.

3. **`Sentry.metrics.count(...)` (9.x) instead of `Sentry.metrics.increment(...)` (7.x)**. The PLAN.md template was for the sentry_flutter 7.x metrics surface; pubspec.yaml pins 9.14.0 where the API is `count(name, value, attributes:)`. Documented as deviation Rule 1 (PLAN template stale on the API name); the semantic contract (counter + PII-safe attributes) is identical.

4. **Telemetry call placed BEFORE the kill-switch check, fire-and-forget via `unawaited(...)`**. The plan explicitly required this — both fired and bypassed evaluations must be observable so dashboards can compute rollback volume. The `gateFired` attribute reflects the actual redirect outcome (`gate.shouldBlock && FeatureFlags.enableCoachHardGate`); the `kill_switch_enabled` attribute reflects the policy decision. Operators can cross-tabulate.

5. **No orchestrator-level telemetry instrumentation.** Per the PLAN spec, instrumenting the orchestrator's `_calibratedArchetypes` early-return would double-count: the route gate fires first, the orchestrator-level guard is defense-in-depth for race protection. The canonical decision site is the route gate.

6. **`OnboardingProvider.legacyReOnboarding` is a named constructor, NOT a default-constructor SharedPreferences read.** Keeps the provider sync + SharedPreferences-free + unit-testable in isolation. The async resolution lives in the SHELL (FutureBuilder), the provider only consumes a bool.

7. **`coachProfile:*` SharedPreferences prefix.** Both flags (`migration_01_5_done` and `needsUsTaxPersonReOnboarding`) follow the existing convention used by other CoachProfileProvider-adjacent flags. Verified via grep.

## Threat Flags

None — this plan stays strictly within the threat surface enumerated in the PLAN's `<threat_model>` block (T-01.5-50 through T-01.5-56):
- T-01.5-50 (Spoofing — local SharedPreferences tampering disables migration): accepted (local-only, signed prod IPA cannot be tampered by non-root).
- T-01.5-51 (Tampering — migration ran but flag not written → re-runs forever): **mitigated** by the `migration_is_idempotent` test + write-before-return ordering in `grandfatherLegacyProfile`.
- T-01.5-52 (Repudiation — no telemetry on the migration itself): **mitigated** by the `legacy_grandfathered` cohort tag on the `gate_decision_by_signal_state` counter — distinguishes natural vs migrated gates in dashboards.
- T-01.5-53 (Information Disclosure — telemetry tags contain PII): **mitigated**. Attributes only contain boolean-shaped strings + archetype slug + cohort marker. No email, no salary, no canton, no name. PII contract enforced inside `recordDecision`.
- T-01.5-54 (DoS — telemetry call blocks gate evaluation): **mitigated** by the `unawaited(...)` fire-and-forget pattern at the call site + the double try/catch inside `recordDecision` (silent-swallow if Sentry SDK is not initialised).
- T-01.5-55 (Elevation of Privilege — grandfathered profile bypasses gate forever): **mitigated** by the orchestrator pre-archetype guard (FutureBuilder + named constructor) that routes flagged users to the US-tax-person Q step BEFORE archetype detection. The `clearReOnboardingFlag` call at the Q's `_answer` ensures the flag is consumed exactly once.
- T-01.5-56 (Tampering — data-truth — migration writes `nationality='CH'`): **mitigated (Codex C1 HIGH fix 2026-05-22)**. Migration is FLAG-ONLY. The nationality field is NEVER written. The `legacy_grandfathered_profile_nationality_remains_null` test is the regression guard. `grep -cn "'CH'" apps/mobile/lib/services/profile_migration_service.dart = 0` is the explicit gate.
