**Wave 02 Plan 04 — R5 Runtime Kill Switch (Codex-flagged release-blocker).**

Per Codex review §R5: "if this is truly P0 legal exposure, require a short-term runtime kill switch for coach advice rendering when archetype is `unknown` or signal set is incomplete, so rollback pressure never reopens the exact same liability window."

Adds a feature flag `enableCoachHardGate` (default true) that wraps the gate logic at BOTH sites (route gate in coach_chat_screen.dart + orchestrator guard in coach_orchestrator.dart). When set to false via the existing server-side `/config/feature-flags` override, the gate is bypassed — this is the emergency rollback path if the gate causes a Sev1 prod incident (e.g. false-positives mass-routing swiss_native users to waitlist).

CRITICAL design choice: the flag default MUST be `true`. Shipping with default `false` would defeat the entire phase. The flag is the panic button, NOT the default config.

Purpose: ship a documented rollback path so we never have to revert the entire 01.5 PR-2 stack if a downstream bug emerges. Per Codex: "rollback pressure never reopens the exact same liability window."
Output: 4 files touched (~50-80 lines), 1 new feature flag, 1 new test file proving both flag states behave correctly.
