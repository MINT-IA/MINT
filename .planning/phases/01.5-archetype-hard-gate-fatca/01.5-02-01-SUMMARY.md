## Decisions Made

1. **Sentinel pattern applied to 4 nullable fields (not 5).** PLAN.md Step 1.9 listed `usTaxPerson, nationality, residencePermit, employmentStatus, arrivalAge` as the tri-state set. `employmentStatus` is structurally non-nullable on CoachProfile (`final String employmentStatus = 'salarie'` default) — a sentinel-pattern parameter would be a no-op because the field cannot accept null. Applied sentinel to the 4 actually-nullable fields. The 5 sentinel tests in the regression guard test file all target `usTaxPerson` + `nationality` (still covered).
2. **Dropped employmentStatus from allSignalsNull / allSignalsAbsent absence checks.** Same constraint as above. The default 'salarie' is treated as "not a positive archetype-discriminating signal" — semantically correct because the archetype getter already short-circuits on `employmentStatus == 'independant'` earlier. Behavior verified by `archetype_returns_unknown_when_all_signals_null` test passing (uses `CoachProfile.defaults()` which leaves employmentStatus at 'salarie' and the other 4 signals null).
3. **`@visibleForTesting debugLppYears` test wrapper instead of widening `_lppYears` directly.** Minimal API surface widening (one symbol, marked test-only by Flutter's annotation). Lint tools and reviewers will see the wrapper is not for production use.
4. **Backend hydration reads both camelCase + snake_case key variants** (`usTaxPerson` ?? `us_tax_person`). Covers both Pydantic v2 alias styles for migration safety — backend may emit either depending on serializer config.
