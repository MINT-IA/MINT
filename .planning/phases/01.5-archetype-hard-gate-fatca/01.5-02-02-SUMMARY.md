### Task 2 — WaitlistService + WaitlistProvider (TDD)

- **WaitlistService.submit()** POSTs to `/api/v1/waitlist` with the X-Anonymous-Session header (sourced via `AnonymousSessionService.getOrCreateSessionId()` — note: the plan template called this `getOrCreate()`, the real name is `getOrCreateSessionId()`).
- Returns a discriminated `WaitlistResult{success, error}` where `error` is one of `WaitlistApiError.{badEmail, badRequest, unauthorized, server, network}`.
- **Status mapping**: 201 + 409 → success (409 = already-enrolled, idempotent UX per UI-SPEC §10) ; 400 → badEmail ; 5xx → server ; 401 → unauthorized ; SocketException / TimeoutException / any other → network.
- **UCA opt-in defense-in-depth (T-01.5-25 mitigation)**: `consentGiven=false` short-circuits with `ArgumentError` BEFORE any I/O. The screen layer also disables the CTA when the checkbox is unchecked.
- **PII-safe (T-01.5-23 mitigation)**: email is NEVER passed to Sentry — error mapping uses HTTP status codes only, never the response body. The MintHttpClient debug-build body capture is bounded by `_bodyLogCap=2000` and stays in `simctl log` (not Sentry).
- **WaitlistProvider** extends ChangeNotifier. `submit()` cycles `initial → submitting → success | error`. `resetError()` returns `error → initial` so the form can be edited + retried.
- **10 tests pass** (target ≥ 9): initial state, 201 transition, 400 → badEmail, 5xx → network, 409 → success (idempotent), SocketException → network, resetError, archetype 'unknown' → 'other' coercion, archetype 'other' direct, consent guard ArgumentError.

## Decisions Made

1. **package:http (not dio)**. The PLAN.md service template was dio-based, but `apps/mobile/pubspec.yaml` has no dio dependency — the project standard is `MintHttpClient` (a `http.BaseClient` subclass) + `MockClient` from `package:http/testing` for tests. Adapted the service body accordingly (same semantics — 201/409 success, 400 badEmail, 5xx/timeout/SocketException network).
2. **`S` not `AppLocalizations`**. `flutter gen-l10n`'s generated abstract class is `S` (see `apps/mobile/lib/l10n/app_localizations.dart:68 — abstract class S {`). Existing screens use `S.of(context)!`. The plan template was incorrect ; corrected in all 3 lib source files + the widget test.
3. **Theme tokens substitution**. `MintColors.porcelaineHandoff` (background) and `MintColors.menthePositive` (success icon) referenced in PLAN.md DO NOT EXIST in `apps/mobile/lib/theme/colors.dart`. Used `MintColors.craieHandoff` (Scaffold background) and `MintColors.success` (check icon foreground) — both already in the design system.
4. **MintErrorState avoided for inline form feedback**. The real `MintErrorState` (`apps/mobile/lib/widgets/common/mint_error_state.dart`) requires `title` + `body` props and is sized for full-page error states with optional retry. For inline form-error feedback it's overkill ; used `Text(...)` styled via `MintTextStyles.bodyMedium(color: MintColors.error)` instead. Still no new widget primitive — `Text` + theme style is part of the existing design system (same approach as the inline disclaimer copy elsewhere).
5. **`getOrCreateSessionId` not `getOrCreate`**. The plan called `AnonymousSessionService.getOrCreate()` — the real static method is `getOrCreateSessionId()` (`apps/mobile/lib/services/anonymous_session_service.dart:76`). Used the correct name via the overrideable `resolveSessionId()` hook on WaitlistService.
6. **B1 fix shipped — WaitlistArgs HERE**. Defined in `apps/mobile/lib/screens/waitlist/waitlist_args.dart` so the WaitlistScreen ctor depends on a same-plan type. Plan 02-03 will `import 'package:mint_mobile/screens/waitlist/waitlist_args.dart'` to construct args at the GoRoute registration site + the gate site, without forward-reference risk.
7. **B3 fix shipped — UCA opt-in checkbox renders**. Per CONTEXT.md §0 (override of UI-SPEC §11 Q3) and Security §5 guardrail #1. `CheckboxListTile(leading affinity, key: 'waitlist-consent-checkbox')` in WaitlistForm, default unchecked, CTA gated on `_consentGiven`. Plan 02-08 composite panel gate will re-verify before merge.
