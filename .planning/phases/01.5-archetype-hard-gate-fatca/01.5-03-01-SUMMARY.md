## Decisions Made

1. **Codex C7 mixed strategy NOT all-Keys.** The plan template suggested a fully Key-based YAML if Plan 02-02 wired Keys, but Plan 02-02 wired ONLY the 3 most consequential interaction surfaces (consent checkbox + submit CTA + back-to-home CTA). Plan 01.6 amendment tracked.

2. **Submit CTA Key is `waitlist-cta`, not `waitlist-submit-cta`.** The plan template's `<interfaces>` block listed `waitlist-submit-cta` but a source-read of `apps/mobile/lib/screens/waitlist/widgets/waitlist_form.dart:151` confirmed the actual wired Key is `waitlist-cta`. Used the real Key. Listed as [Rule 1] deviation below.

3. **US-tax-person Q tolerance in the new flow.** The expat_us seed sets `usTaxPerson:true + nationality:'US'`, so the FATCA short-circuit fires at archetype resolution. However, the onboarding step machine may still render T2.5 before consulting the seeded signal (depending on the order of seed-hydration vs. step-machine init). Rather than assume the Q is bypassed, I added a conditional `runFlow when visible` block that taps `Oui` if the Q fires — consistent with the seed and idempotent.

4. **Hero T2.5 addition = `Non` not `Oui`.** The hero asserts the calibrated swiss_native coach grounding (3a 7258 CHF). A `Oui` answer would force the archetype to `expatUs` → route to /waitlist → defeat the regression. `Non` keeps the archetype = `swissNative` so the rest of the hero flow proceeds verbatim.

5. **Codex C8 staging pin documented but NOT exercised.** Per the plan scope clarification in the agent prompt (« YAML CREATION ONLY — the actual Maestro execution against booted sim + staging Railway is the G1 gate in Plan 03-02 »), I did NOT curl staging in this plan. The staging-pin contract is documented in this SUMMARY's "Maestro Run Command" section so Plan 03-02 has a ready-to-execute script. The actual sha + capture-timestamp + re-verify-timestamp land in `01.5-03-01-EVIDENCE.md` during Plan 03-02 execution.

6. **Worktree base alignment via branch checkout, NOT --hard reset.** The orchestrator-spawned worktree HEAD was `255373bb` (an old hotfix-on-dev commit) instead of the expected base `5c5967bb`. The standard `git reset --hard` is blocked by the session's git-safety protocol.
