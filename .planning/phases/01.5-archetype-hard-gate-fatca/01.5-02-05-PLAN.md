**Strategy adopted (REVISED 2026-05-22 per Codex C1 HIGH blocker — flag-based grandfathering, NO nationality rewrite):**

Codex C1 (REVIEWS.md 2026-05-22) — **`nationality='CH'` rewrite on legacy null-nationality profiles is data-truth corruption** (silently writing CH-nationality to users who didn't declare it is the same class of harm 01.5 is designed to PREVENT — even if FATCA Q corrects it next session, the intermediate state is the bug-class this phase exists to close).

Revised strategy:
- **Leave `nationality` UNTOUCHED on legacy profiles.** Never write CH to a profile whose user didn't self-declare CH.
- **Set `needsUsTaxPersonReOnboarding=true` flag** (SharedPreferences) on legacy profiles where `usTaxPerson==null AND nationality==null` — explicitly marks the profile as "legacy pre-fix, needs FATCA Q on next session".
- **Gate evaluation logic**: when the archetype getter sees a legacy-grandfathered profile (re-onboarding flag set) WITHOUT the US-tax-person Q answered yet, the onboarding orchestrator routes to the US-tax-person Q step FIRST — BEFORE coach. The archetype getter's normal "all signals null → unknown" branch is bypassed because the re-onboarding flag forces the Q step ahead of any archetype resolution. Only after US-tax-person Q is answered does the archetype resolve normally from the fresh FATCA signal.
- **Telemetry counter** `gate_decision_by_signal_state` at every gate evaluation (signal state breakdown including the re-onboarding flag) so we can observe the churn rate AND detect unexpected pass-throughs.

Rationale: full hard re-onboarding for every legacy user is a UX nuclear option that risks mass churn (Gemini R7 concern). The 1-question forced re-onboarding captures FATCA without the trauma AND respects the data-truth boundary (Codex C1 fix). The grandfathering window is the first 30 days post-ship; after that, any profile still missing the FATCA signal is routed to the standard gate flow.

    ```dart
    import 'package:shared_preferences/shared_preferences.dart';

    import '../models/coach_profile.dart';

    /// R7 legacy-user-lockout migration for sub-phase 01.5.
    ///
    /// Pre-fix profiles cached with `nationality == null` AND `usTaxPerson == null`
    /// would otherwise be reclassified as FinancialArchetype.unknown (per plan 01
    /// Task 1 getter), kicking them all to /waitlist on next app open. To avoid
    /// mass churn, FLAG them for a forced one-question US-tax-person re-onboarding
    /// on their next session.
    ///
    /// **CRITICAL — data-truth boundary (Codex C1 HIGH fix, REVIEWS.md 2026-05-22):**
    /// This migration MUST NOT write any value to the profile's nationality field.
    /// Writing `nationality='CH'` to a user who didn't declare it is the exact class
    /// of data-truth corruption sub-phase 01.5 is designed to PREVENT. Even if the
    /// FATCA Q corrects the archetype next session, the intermediate state is the
    /// bug-class this phase exists to close.
    ///
    /// The grandfather path is FLAG-BASED: set `needsUsTaxPersonReOnboarding=true`
    /// in SharedPreferences. The onboarding orchestrator reads this flag BEFORE
    /// archetype detection and routes the user to the US-tax-person Q step. Only
    /// AFTER the Q is answered does the archetype getter resolve from the fresh
    /// FATCA signal.
    ///
    /// Idempotent: protected by a SharedPreferences flag `coachProfile:migration_01_5_done`.
    class ProfileMigrationService {
      ProfileMigrationService({SharedPreferences? prefs}) : _prefsFuture =
            prefs != null ? Future.value(prefs) : SharedPreferences.getInstance();

      final Future<SharedPreferences> _prefsFuture;

      static const _doneFlag = 'coachProfile:migration_01_5_done';
      static const _reOnboardFlag = 'coachProfile:needsUsTaxPersonReOnboarding';

      /// Returns true if migration FLAGGED a legacy profile for re-onboarding,
      /// false if no-op (new profile, or migration already done, or profile
      /// already had positive signals).
      ///
      /// **No nationality rewrite — flag-based only.** See class doc for rationale.
      Future<bool> grandfatherLegacyProfile({
        required CoachProfileProvider provider,
      }) async {
        final prefs = await _prefsFuture;
        if (prefs.getBool(_doneFlag) == true) {
          return false; // idempotent: already migrated
        }

        final profile = provider.profile;
        if (profile == null) {
          // First-launch user with no cached profile — nothing to grandfather.
          await prefs.setBool(_doneFlag, true);
          return false;
        }

        // Only grandfather if BOTH usTaxPerson and nationality are null. Any
        // positive signal means the user already provided a discriminating
        // input — gate should fire correctly for them per plan 01 getter.
        final isLegacyAmbiguous = profile.usTaxPerson == null
            && profile.nationality == null;
        if (!isLegacyAmbiguous) {
          await prefs.setBool(_doneFlag, true);
          return false;
        }

        // Codex C1 HIGH fix (2026-05-22): FLAG ONLY. Do NOT write any value
        // to the profile's nationality field. The re-onboarding flag is the
        // sole signal; the orchestrator reads it BEFORE archetype detection
        // and forces the US-tax-person Q step. Once the Q is answered, the
        // archetype getter resolves from the fresh signal (usTaxPerson and/or
        // nationality entered via that Q's UX).
        await prefs.setBool(_reOnboardFlag, true);
        await prefs.setBool(_doneFlag, true);
        return true;
      }

      /// Read by the US-tax-person screen or the onboarding orchestrator to
      /// detect whether a returning legacy user must answer the FATCA Q now.
      Future<bool> needsUsTaxPersonReOnboarding() async {
        final prefs = await _prefsFuture;
        return prefs.getBool(_reOnboardFlag) ?? false;
      }

      /// Called after the user answers the US-tax-person Q post-migration.
      Future<void> clearReOnboardingFlag() async {
        final prefs = await _prefsFuture;
        await prefs.remove(_reOnboardFlag);
      }
    }
    ```
