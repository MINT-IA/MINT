**Wave 02 Plan 05 — R7 Legacy User Lockout migration + R4 telemetry counter (Gemini + Codex risks).**

R7 (Gemini): "changing the `nationality == null` fallback from `swissNative` to `unknown` will immediately kick every existing user who hasn't completed their profile to the waitlist. You are effectively forcing a Hard Re-onboarding for a large segment of your base. If you aren't ready for that churn, you need a migration flag."

R4 telemetry portion (Codex): "Add telemetry counter `gate_decision_by_signal_state` to detect unexpected pass-through."

**Strategy adopted (per planner's product call, documented):**

Per Gemini's two options "EITHER force re-onboarding flow with proper UX OR grandfathered swissNative for pre-fix profiles + telemetry to track churn", we choose the SAFER option:
- **Grandfather** existing cached profiles created BEFORE this plan ships as `swissNative` (NOT route to /waitlist) — they keep using the coach as before
- **Force the US-tax-person Q on their NEXT session** via a re-onboarding flag (1-question only, NOT full re-onboarding) — this captures the FATCA signal without disrupting their existing coach access
- **Emit telemetry** `gate_decision_by_signal_state` at every gate evaluation (signal state breakdown) so we can observe the churn rate AND detect unexpected pass-throughs

Rationale: full hard re-onboarding for every legacy user is a UX nuclear option that risks mass churn. The 1-question re-onboard captures FATCA without the trauma. The grandfathering window is the first 30 days post-ship; after that, profiles still missing the signal are routed to /waitlist (graceful transition).

**Dependency-correctness note (B2 fix, 2026-05-22):** plan 02-04 (kill switch wrap on `coach_chat_screen.dart`) and this plan (telemetry instrumentation on `coach_chat_screen.dart`) both modify the SAME file inside the gate block.     import 'package:shared_preferences/shared_preferences.dart';

    ```dart
    import '../models/coach_profile.dart';
    import '../providers/coach_profile_provider.dart';

    /// R7 legacy-user-lockout migration for sub-phase 01.5.
    ///
    /// Pre-fix profiles cached with `nationality == null` would otherwise be
    /// reclassified as FinancialArchetype.unknown (per plan 01 Task 1 getter),
    /// kicking them all to /waitlist on next app open. To avoid mass churn,
    /// grandfather them as swissNative AND flag them for a forced one-question
    /// US-tax-person re-onboarding on their next session.
    ///
    /// Idempotent: protected by a SharedPreferences flag `coachProfile:migration_01_5_done`.
    class ProfileMigrationService {
      ProfileMigrationService({SharedPreferences? prefs}) : _prefsFuture =
            prefs != null ? Future.value(prefs) : SharedPreferences.getInstance();

      final Future<SharedPreferences> _prefsFuture;

      static const _doneFlag = 'coachProfile:migration_01_5_done';
      static const _reOnboardFlag = 'coachProfile:needsUsTaxPersonReOnboarding';

      /// Returns true if migration ran (legacy grandfather happened),
      /// false if no-op (new profile, or migration already done, or profile
      /// already had positive signals).
      Future<bool> grandfatherLegacyProfile({
        required CoachProfileProvider provider,
      }) async {
        final prefs = await _prefsFuture;
        if (prefs.getBool(_doneFlag) == true) {
          return false; // idempotent: already migrated
        }

        final profile = provider.profile;
        if (profile == null) {
          // First-launch user with no cached profile — nothing to grandfather.
          await prefs.setBool(_doneFlag, true);
          return false;
        }

        // Only grandfather if BOTH usTaxPerson and nationality are null. Any
        // positive signal means the user already provided a discriminating
        // input — gate should fire correctly for them per plan 01 getter.
        final isLegacyAmbiguous = profile.usTaxPerson == null
            && profile.nationality == null;
        if (!isLegacyAmbiguous) {
          await prefs.setBool(_doneFlag, true);
          return false;
        }

        // Grandfather: write nationality='CH' to keep the user on the
        // swissNative coach path, AND flag for forced US-tax-person Q on
        // next session. Do NOT touch usTaxPerson — it stays null (tri-state)
        // so the re-onboarding step can write the true value.
        await provider.updateProfile(profile.copyWith(nationality: 'CH'));
        await prefs.setBool(_reOnboardFlag, true);
        await prefs.setBool(_doneFlag, true);
        return true;
      }

      /// Read by the US-tax-person screen or the onboarding orchestrator to
      /// detect whether a returning legacy user must answer the FATCA Q now.
      Future<bool> needsUsTaxPersonReOnboarding() async {
        final prefs = await _prefsFuture;
        return prefs.getBool(_reOnboardFlag) ?? false;
      }

      /// Called after the user answers the US-tax-person Q post-migration.
      Future<void> clearReOnboardingFlag() async {
        final prefs = await _prefsFuture;
        await prefs.remove(_reOnboardFlag);
      }
    }
    ```

    ```dart
    import 'package:sentry_flutter/sentry_flutter.dart';

    import '../../models/coach_profile.dart';

    /// R4 (Codex) — observability for the sub-phase 01.5 archetype HARD GATE.
    ///
    /// Records every gate evaluation with the signal state and decision outcome
    /// so we can detect:
    ///   - unexpected pass-through (gate did not fire when it should have)
    ///   - mass false-positives (high gate_fired rate on swiss_native users)
    ///   - kill-switch bypass volume
    ///
    /// Sentry metrics API (Sentry.metrics.increment, requires sentry_flutter ≥ 7.19)
    /// OR fallback breadcrumb path (works on sentry_flutter ≥ 6.x). The fallback
    /// is selected at AUTHORING time by checking pubspec.yaml — DO NOT rely on
    /// the runtime try/catch to discover an API mismatch (it is a compile error
    /// on lower versions, not a runtime throw). W3 fix (2026-05-22).
    class GateDecisionTelemetry {
      static void recordDecision({
        required CoachProfile profile,
        required FinancialArchetype computedArchetype,
        required bool gateFired,
        required bool killSwitchEnabled,
      }) {
        final tags = <String, String>{
          'archetype': computedArchetype.backendName,
          'gate_fired': gateFired.toString(),
          'kill_switch_enabled': killSwitchEnabled.toString(),
          'signal_us_tax_person': _stateLabel(profile.usTaxPerson),
          'signal_nationality': profile.nationality == null ? 'null' : 'set',
          'signal_residence_permit': profile.residencePermit == null ? 'null' : 'set',
          'signal_employment_status': profile.employmentStatus == null ? 'null' : 'set',
          'signal_arrival_age': profile.arrivalAge == null ? 'null' : 'set',
        };

        // Counter increment (Sentry metrics API). Only emit if sentry_flutter
        // pinned in pubspec.yaml is ≥ 7.19 (confirmed in read_first). Otherwise
        // ship breadcrumb-only and remove the increment call. The runtime
        // try/catch below is a defense-in-depth guard for plugin init failures,
        // NOT a way to detect API absence.
        try {
          Sentry.metrics.increment(
            'gate_decision_by_signal_state',
            value: 1,
            tags: tags,
          );
        } catch (_) {
          // Fallback: breadcrumb so we still have observability without metrics API.
          Sentry.addBreadcrumb(Breadcrumb(
            category: 'gate.decision',
            message: 'gate_decision_by_signal_state',
            data: tags,
            level: SentryLevel.info,
          ));
        }
      }

      static String _stateLabel(bool? signal) {
        if (signal == null) return 'null';
        return signal ? 'true' : 'false';
      }
    }
    ```
