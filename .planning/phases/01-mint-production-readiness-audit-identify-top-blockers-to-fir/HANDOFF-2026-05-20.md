## Subagent vs Skill primer (Julien's question this session)

- **Agent / Task() calls** = separate context window + token budget per call. Receive a focused prompt, return one summary. **Do NOT pollute orchestrator context** with intermediate work. Parallelizable.
- **Skill tool calls** (e.g., `/gsd-discuss-phase`, `/ship`, `/review`) = run **IN the orchestrator's context**. The workflow `.md` files are loaded into the orchestrator window. Each skill invocation adds tokens.

⇒ For heavy multi-agent work (mapping, research, panel reviews), prefer `Agent` calls. For interactive workflows that need state in main context (GSD discuss/plan/execute), expect token cost.
