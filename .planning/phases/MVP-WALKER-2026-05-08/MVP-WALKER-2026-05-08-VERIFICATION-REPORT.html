Fix shipped this session — saveToken keychain fallback

Why: Étape 1 was hard-blocked. AuthService.saveToken on the iOS sim threw a PlatformException from flutter_secure_storage *after* staging had already created the user via HTTP 201. The exception fell through to AuthError.genericError → user saw « Action impossible pour le moment », orphan account on staging.

Forensic citation: SharedPreferences plist after a failed submit contained only flutter.mint_beta_disclosure_seen and flutter.analytics_session_id. None of the keys written by register_screen.dart:95–100 (accepted_cgu_v1, consent_*, q_birth_year, q_firstname) were present — proves register() returned false.

Patch: apps/mobile/lib/services/auth_service.dart — in-memory cache populated *before* the keychain write attempt; saveToken/getToken/refresh/logout each wrap keychain calls in try/catch and use the in-memory cache as fallback. Mirrors PR #516's biography keychain-fallback pattern (commit 3d7a7559).

Tests: 4 new regression tests in test/services/auth_service_test.dart « keychain failure fallback » (saveToken doesn't throw / getToken returns memory / everything-fails returns null / logout clears memory). All 27 tests in that file pass; combined auth tests across 3 files: 43 pass.
