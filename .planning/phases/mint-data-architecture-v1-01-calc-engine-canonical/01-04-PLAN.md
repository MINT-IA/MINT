### Staging aging policy — concrete state machine (codex HIGH #3 resolved)

State file: `.planning/state/regulatory-codegen-aging.json` (created on first staging-down event).

```json
{
  "first_staging_down_at": "2026-05-17T14:00:00Z",
  "last_staging_down_at": "2026-05-17T14:00:00Z",
  "last_staging_up_at": "2026-05-17T13:00:00Z",
  "consecutive_down_days": 0,
  "escalation_level": 0
}
```

State transitions (computed at workflow run time):
- **Staging UP** : write `last_staging_up_at = now` ; reset `consecutive_down_days = 0` ; reset `escalation_level = 0` ; delete `first_staging_down_at`.
- **Staging DOWN** : if `first_staging_down_at` is missing, set to `now` ; update `last_staging_down_at = now` ; recompute `consecutive_down_days = (now - first_staging_down_at).days`.

Escalation thresholds (consecutive_down_days):
- **0-6 days** : `escalation_level = 0`. Workflow logs a warning, exits 0.
- **7-13 days** : `escalation_level = 1`. Workflow posts a PR comment (« regulatory-codegen has been operating against the local fixture for 7+ days — staging drift is invisible. Restore staging or accept potential drift »). Exits 0.
- **14-27 days** : `escalation_level = 2`. Workflow auto-opens a GitHub Issue titled `[STAGING-AGING] regulatory-codegen drift visibility blocked` (deduplicated by title — only one open at a time). Exits 0.
- **>= 28 days** : `escalation_level = 3`. Workflow EXITS 1 (HARD BLOCK on PR). Path back to green: restore staging or merge a PR that explicitly accepts the aging by bumping a documented allowlist counter.

Recovery: when staging is detected UP after an aging episode, the workflow:
1. Resets the state file.
2. Re-runs codegen against staging.
3. If hash differs from committed Dart file, fails the PR with a regen instruction (the normal staging-up failure path).
4. If hash matches, exits 0.

This policy ensures « staging-soft » NEVER becomes invisible long-term drift — codex HIGH #3 closed.
