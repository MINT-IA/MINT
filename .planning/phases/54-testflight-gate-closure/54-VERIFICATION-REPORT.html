Local diagnosis:

  • pubspec.yaml: 0 references to google_mlkit_* (only the 2026-04-17 removal comments).
  • pubspec.lock: 0 MLKit references (committed file is clean).
  • .flutter-plugins-dependencies on dev tip: 0 MLKit entries.
  • apps/mobile/ios/Podfile.lock: 0 MLKit references (committed file is clean).
  • Local cd apps/mobile/ios && pod deintegrate && pod install --repo-update: 27 pods installed cleanly, no MLKit conflict.

Conclusion: the CI runner produces a different resolution from local. Most plausible cause = a stale subosito/flutter-action@v2 cache (cache: true on testflight.yml line 158) that restores a pre-2026-04-17 pub-cache state where google_mlkit_* packages still exist, then flutter pub get short-circuits or symlinks them anyway. Genuinely a Plan 54-03 blocker that needs Julien's call between (a) invalidate the cache via cache-key: ${{ hashFiles('apps/mobile/pubspec.lock') }}, (b) add flutter clean as a workflow step before flutter pub get, (c) drop cache: true entirely.
