# Phase 91 — Plan 01: Persona Toggle Settings Migration (VIVANT-04)

## Goal
Move the « Calme / Direct / Sans filtre » persona chips out of `coach_chat_screen.dart` into a dedicated `/settings/coach-tone` screen with a persistent `SharedPreferences` flag, and wire the chosen tone into every `/coach/chat` request.

- `apps/mobile/lib/services/coach/coach_tone_preference.dart` — **NEW**, enum `CoachTonePreference { calm, direct, sansFilter }` + `SharedPreferencesAsync`-backed `load()` / `save()` helpers, default `calm`.

## Steps
1. Create `coach_tone_preference.dart` with the enum + 2 async helpers backed by `SharedPreferencesAsync` (key `coach_tone_preference`, default `calm`). Unit-test the round-trip.
2. Create `coach_tone_screen.dart` with three radio-tile rows (Calme / Direct / Sans filtre). On tap → `CoachTonePreference.save(value)` + `Navigator.pop()`. **Reuse existing chip ARB keys** (grep `app_fr.arb` for `tonChipCalm`, `tonChipDirect`, `tonChipSansFilter` or equivalent ; do NOT add new keys).
3. Register `/settings/coach-tone` in `app.dart` (alphabetical insertion).
4. Add the « Ton du coach » `ListTile` entry to the existing settings screen (reuse `settings_*` ARB key conventions ; if a generic « settings.coachTone » key already exists, reuse ; else reuse the same chip label).
5. Delete the inline tone chip widget block from `coach_chat_screen.dart` (around line 2340-2400 per CONTEXT). Leave the `_log('coach.tone.changed', ...)` log site at `:898` intact but source the value from `CoachTonePreference.load()`.
6. In the chat-call site, await the preference once on screen mount, cache in state, and pass `tone: pref.name` in every `/coach/chat` POST body.
7. Backend : extend `coach_chat.py` request schema with `tone: Optional[str]`. In `claude_coach_service.py`, map the 3 tone values onto the existing `_TONE_INTENSITY_BLOCK` strings (calm=block already used as default, direct=intensity-4 equivalent, sansFilter=intensity-5 equivalent) — no new prompt template, just route the existing 3 blocks via the new enum.
8. Run `flutter analyze`, `flutter test`, `cd services/backend && python3 -m pytest tests/ -q`.
9. Run `flutter gen-l10n` to confirm no ARB keys were silently added (parity must stay).
