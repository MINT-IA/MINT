# Personal Financial Wiki — v2.14 / v3.0 milestone candidate

## TLDR

Productize Karpathy's LLM Wiki Pattern as MINT's user-facing knowledge layer : each user gets a personal financial wiki — pages generated by the coach across sessions, cross-referenced, exportable — that compounds over months. This becomes the structural answer to the « Voir clair, décider seul. » brand line and the principal v3.0 differentiator vs Cleo / VIAC / Frankly / Notion-and-LLM hybrids.

## Context

The Wiki Pattern (PR #502) adopts Karpathy's gist for MINT's *internal* `.planning/` knowledge accumulation. Concept transposes naturally to the *user* side : a stateless coach-chat is the same anti-pattern as stateless RAG ; users have to re-explain their situation every session because nothing accumulates.

Four pieces converge :

1. **Cleo brand line** « Voir clair, décider seul. » — currently lives as copy ; this proposal makes it infrastructure-driven (we maintain the dossier that makes the decision possible, we don't make the decision).
2. **MINT mission** — Swiss financial lucidity, 18-99, 18 life events. Each life event triggers analysis the user re-needs years later (3a optimization revisited at age 50, FATCA implications at age 35 + at age 60).
3. **MINT compliance posture** — LSFin / FDPIC / banned-terms guardrails. The wiki's schema is MINT's compliance contract — LLM-generated pages MUST pass the regex library + archetype gate + accent integrity.
4. **MINT engineering investment** — financial_core/ calculators, ConfidenceScorer, ARB 6 langs, anonymous → register flow. Already in place. The personal wiki is the consumption layer that surfaces this work.

## Decision

**Proposed v2.14 or v3.0 milestone : « Personal Financial Wiki »**.
Status remains **Proposed** until panel convocation post-v2.13 Phase 92 ship gate ; this artifact reserves the slot and locks the doctrine.

**Scope frame (4 phases, ~6-8 weeks effort estimate)** :

- **Phase A — User-side `raw/`** : encrypted-at-rest document vault (LPP cert, 3a statements, IFD, relevés). Builds on existing scan-handoff infra (Wave C). Per-user E2EE optional v3.0 ; v2.14 ships server-side encryption with user-held key derivation.
- **Phase B — User-side `wiki/`** : LLM-generated markdown pages per topic (e.g. `mon-3a-strategy.md`, `lpp-rachat-evaluation.md`, `marge-fiscale-2026.md`). One page per coaching analysis. Pages auto-cross-reference (`[[topic-name]]` syntax). LSFin regex enforced on every page write. ConfidenceScorer.EnhancedConfidence on every numeric.
- **Phase C — Wiki UI viewer** : Flutter screen `WikiScreen` — list (INDEX), individual page (read-only render), cross-reference navigation. Search via FTS5/SQLite at user count. Theme-respecting (MintColors / Fraunces typography panel-locked).
- **Phase D — Export + Share** : PDF export of the personal wiki ; secure-share-link to fiscaliste / partner / conjoint with redaction levels (full / aggregated / removed-PII). Audit log of share events per FDPIC art.6.

**Compounding KPI** : avg wiki page count per active user × cross-reference density × revisit rate. Target month 6 : ≥ 8 pages average, ≥ 3 cross-refs per page, ≥ 40 % revisit rate of pages older than 30 days.

**Differentiation thesis (vs competitive landscape)** :

| Player | Stateful wiki | LLM-generated | Cross-references | Export | LSFin-locked |
|--------|---------------|---------------|------------------|--------|--------------|
| Cleo (UK) | ❌ chat-only | partial | ❌ | ❌ | n/a — UK-FCA |
| VIAC / Frankly / Selma (CH) | ❌ transactional | ❌ | ❌ | ❌ | partial |
| Notion + LLM | ✓ user-built | ✓ | ✓ | ✓ | ❌ user-managed |
| ChatGPT / Claude personal | ❌ stateless per-session | ✓ | ❌ | ❌ | ❌ |
| **MINT v3.0 Personal Wiki** | ✓ | ✓ | ✓ | ✓ | ✓ panel-locked |

## Counter-arguments and data gaps

**Strongest opposing view :** Personal wiki is feature-creep on a Swiss financial lucidity app. Users hire MINT to get answers, not to maintain a knowledge base ; making them « owners » of a wiki shifts cognitive load back onto them. Notion's failure mode (« people abandon Notion setups for the same reason they abandoned Evernote — maintenance costs grow faster than value » per Karpathy article) might apply directly. The compounding metric assumes users return ; if MINT's natural churn is high, the wiki is empty for most.

**What this source does not address :** Empirical user demand. We have ZERO MINT-cohort data on whether users want a personal financial dossier vs prefer transactional « give me the answer ». The 4-phase scope estimate is back-of-envelope ; UI / export complexity often grows 2-3× post first-prototype. No measured comparison vs « let users export individual analyses on demand » (lighter alternative).

**What would change this conclusion :** (a) Post-v2.13 launch survey signal that ≥ 30 % of users name « track my situation over time » as top-3 expected MINT benefit → stronger green light. (b) Regulatory clarification that MINT-generated wiki pages constitute « financial advice » under LSFin (would force scope reduction or licensing track). (c) Anthropic / OpenAI shipping native per-user persistent memory in the API → would reduce MINT differentiation if every chatbot does this for free. (d) Notion or competitor shipping « financial wiki for non-tech » before v3.0 → invalidates first-mover thesis.
