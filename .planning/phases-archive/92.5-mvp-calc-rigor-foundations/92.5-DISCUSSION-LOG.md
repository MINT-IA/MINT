## Gray areas discussed (Product-Leader-decided, no AskUserQuestion)

### GA-1 — Backend Python calc-parity scope (THE BLOCKER)

**Question framed:** ROADMAP §92.5 success criterion #1 says « 200 frozen profile fixtures through both `apps/mobile/lib/services/financial_core/` and `services/backend/app/services/` (Python) ». But Python side has zero mirror class for the 3 locked Dart calculators (`AvsCalculator.computeMonthlyRente`, `LppCalculator.projectToRetirement`, `TaxCalculator.capitalWithdrawalTax`). What's the actual scope?

**Verification performed:**
```
grep -rln "computeMonthlyRente\|projectToRetirement\|capitalWithdrawalTax" services/backend/
→ (empty)

wc -l apps/mobile/lib/services/financial_core/{avs,lpp,tax}_calculator.dart
→ 265 + 471 + 491 = 1227 total

grep -rln "class AvsCalculator\|class LppCalculator\|class TaxCalculator" services/backend/
→ (empty)
```

**Three options considered:**

| Option | Description | Pros | Cons |
|--------|-------------|------|------|
| **A — Full port** | Add plan 92.5-04 « Backend calc-parity scaffold » porting ~1200 LOC Dart→Python | Faithful to ROADMAP letter (200 fixtures) | Scope creep (+4-6d → 9-11d total budget) ; error-prone (porting bugs = false-positive divergences) ; contradicts ADR-2026-02-23 (Mobile is canonical) |
| **B — Scope-cut + defer** | Differential on existing parity surface (80–100 fixtures), full coverage in backlog 999.4 / Phase 92.6 | Stays in 5d budget ; preserves ADR-2026-02-23 ; immediate G6 value on the partial surface | G6 only covers ~40-50% of calc surface until 92.6 lands |
| **C — No-differential** | Skip CALC-01 entirely, ship only property + ESTV | Simplest | Violates ROADMAP CALC-01 success criterion explicitly ; loses key axis |

**Decision: Option B.**

**Rationale:**
1. Spirit of ROADMAP §92.5 = mechanical CI grounding before Phase 94 citation gate. 80–100 fixtures on real parity surface delivers that ; 200 fixtures on a Python port delivers porting bugs.
2. ADR-2026-02-23 makes Mobile canonical. Full Python port is double-bookkeeping that contradicts the anchor ADR.
3. Phase 94 (citation gate) hasn't yet proven Backend MUST compute canonical numbers — it might consume them as opaque input from Mobile or from arbitrage_engine GroundingPack. Until that's proven, full port is YAGNI.
4. Phase 92.6 backlog item triggers cleanly when/if Phase 94 demonstrates Backend ownership of citation numbers.

Locked in CONTEXT.md as **D-01 / D-02 / D-03**.

### GA-2 — Differential harness invocation mechanics

**Question framed:** How does Python pytest invoke Dart calc? `dart compile exe` vs `flutter test --machine` vs `dart run` JIT vs subprocess-per-fixture vs single-batch JSONL pipe.

**Decision (no debate, engineering best-practice):** `dart compile exe` once per CI run → single binary `build/calc_harness_dart` → spawned once per pytest session (fixture-scoped subprocess) → JSONL stdin/stdout for the 80–100 fixtures.

**Rationale:** Single binary build amortizes the ~10s Dart compile across 80–100 fixtures. Per-fixture subprocess would be ~200ms × 80 = 16s overhead per test run. Stream JSONL is the standard pattern for cross-language test pipes (also used in extractor v2 Phase 91 eval pack).

Locked as **D-04 / D-05 / D-06 / D-07**.

### GA-3 — Frozen 200-fixture (now 80–100) provenance

**Question framed:** Synthetic Hypothesis-generated vs hand-curated archetype matrix vs Phase 91 eval pack reuse.

**Decision:** Deterministic matrix — 8 archetypes × 5 cantons × 2 phases-de-vie = 80, optional +20 hand-curated edge cases = 100 max.

Locked as **D-08 / D-09 / D-10**.

### GA-4 — ESTV oracle capture method

**Question framed:** Manual capture (Julien types 50 profiles into ESTV calc) vs Playwright headless scraping vs hybrid.

**Decision:** Playwright headless scraping (one-shot Python script ~50–80 LOC) run manually by Julien on annual ESTV publication cycle (Nov–Dec).

**Rationale:**
- Manual capture for 50 vectors = 1.5h of clicking. Annually. Boring + error-prone.
- Playwright once-and-done is ~50 LOC, runs in <2min, and is re-runnable when ESTV updates barèmes.
- Annual cadence (not per-CI) avoids ESTV rate-limiting / captcha concerns.
- WARN-only freshness lint (not FAIL) keeps CI from blocking when ESTV is down or barème publication is delayed.

Locked as **D-11 / D-12 / D-13 / D-14**.

### GA-5 — Hypothesis property suite

**Question framed:** Where do invariants live? Python only? Dart only? Both?

**Decision:** Python invariants on the parity surface (4 of the 8 from ROADMAP — bounds, monotonicity, RAMD cap, anticipation sign). Dart-side mirror invariants for the calculator-internal rounding (4 of 8 — Mobile vs Backend rounding consistency, but tested as Mobile-internal since no Python mirror exists yet).

**Rationale:**
- ROADMAP §92.5 success criterion #2 lists 8 invariants but doesn't fix WHERE they live. (a)–(d) are general invariants computable from helper outputs ; (e)–(h) are Mobile↔Backend rounding consistency, which require both sides to compute. Until 92.6 ports calc to Python, (e)–(h) are tested as « Mobile rounds the same way regardless of input », i.e., Mobile-internal stability.
- This split honors the ROADMAP intent (8 invariants asserted) without requiring the Python port.

Locked as **D-15 / D-16 / D-17**.

### GA-6 — G6 gate wiring & blocking policy

**Question framed:** Hard-block from day 1 vs warn-only ramp-up. Path-trigger detection. PERIMETERS.md schema extension.

**Decision:** Hard-block from day 1, scoped to PRs touching `apps/mobile/lib/services/financial_core/**`, `services/backend/app/services/**`, or `services/backend/app/constants/social_insurance.py`. PERIMETERS.md gets a 6th row, additive only. G1–G5 unchanged. Other perimeters skip G6.

**Rationale:**
- Warn-only is the failure mode we are explicitly preventing — silent calc drift. If G6 doesn't block, it's theatre.
- Path-trigger keeps the noise low: a UI-only PR doesn't run calc-rigor.yml.
- Memory `feedback_perimeter_5_gates.md` is preserved (G6 is additive ; perimeters not touching calc remain on G1–G5).
- Failure-comment template (D-20) names Mobile as canonical to avoid debate when divergence reports.

Locked as **D-18 / D-19 / D-20 / D-21**.
