## P2 Findings

### P2-1 · ES/PT locale silent fallback to English form

**File:** `apps/mobile/lib/screens/document_scan/avs_guide_screen.dart` (top-level function)

```dart
const suffixByLanguage = <String, String>{
    'fr': 'f', 'de': 'd', 'it': 'i',
    'en': 'e', 'es': 'e', 'pt': 'e',   // ES/PT: 404 on native endpoints
};
final suffix = suffixByLanguage[locale.languageCode.toLowerCase()] ?? 'e';
```

The comment documents that `.es` and `.pt` endpoints return 404 at time of writing. The unit test (`avs_guide_screen_test.dart`) correctly codifies the expected `.e` fallback. **Risk:** if the government later publishes working Spanish/Portuguese direct endpoints, users will continue receiving the English form. No data-integrity concern, but UX degradation. Recommend a scheduled re-verification in the backlog.

### P2-2 · Pre-existing hardcoded French strings in dormant-engine files

**Files:** `cross_pillar_calculator.dart`, `bayesian_enricher.dart`, `monte_carlo_service.dart`

These files retain French-language strings in `tradeOff`, `label`, `action`, `disclaimer`, and `alerte` fields, all annotated `// lint-ignore: dormant engine; no production renderer`. This is localization debt that predates this PR; the PR correctly marks (but does not resolve) it. **Risk:** if any dormant engine consumer is wired to a renderer without going through the localization layer, French strings will appear in non-French locales. Not introduced here, not a regression.

### P2-3 · `TornadoSensitivityService._project` over-strict NaN gate on `missingFields.isNotEmpty`

**File:** `apps/mobile/lib/services/financial_core/tornado_sensitivity_service.dart`

```dart
if (!result.avsIncluded || result.missingFields.isNotEmpty) {
    return double.nan;
}
```

Any non-empty `missingFields` — including non-AVS fields — causes a tornado variant to return NaN and be silently dropped from the ranking. In practice this is guarded: the tornado widget is only rendered when `_hasCompleteProjection` is true, which requires `tauxRemplacementBase != null` (implying no blocking missing field). The risk is theoretical for the current call-site, but if `TornadoSensitivityService.compute` is ever called outside that guard, it will silently return an empty ranking for profiles with minor gaps. A comment documenting this pre-condition on the public `compute` method would prevent future confusion.

### P2-4 · `completeRemainingSequence` test helper has unbounded loop with soft cap

**File:** `apps/mobile/test/screens/coach/retirement_dashboard_test.dart` (~line 230)

```dart
while (current.action is AdvanceAction) {
    ...
    expect(eventIndex, lessThanOrEqualTo(20));
}
```

The loop advances until `CompleteAction` is reached, guarded only by an assertion. If the sequence definition has a cycle or is misconfigured, the test will spin 20 iterations before failing rather than failing immediately with a clear error. Not a correctness defect in the production path, but a test-quality concern.
