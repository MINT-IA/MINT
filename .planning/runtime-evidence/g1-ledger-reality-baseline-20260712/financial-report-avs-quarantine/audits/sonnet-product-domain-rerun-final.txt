## P2 findings

### P2-A · Misleading "estimée" label in LPP pending row

**File:** `apps/mobile/lib/widgets/report/retirement_projection_card.dart:84`
```
_infoRow(l.futurRenteLpp, l.coverageCheckAVerifier)
```
`futurRenteLpp` resolves to **"Rente LPP estimée"** in French (verified in `app_fr.arb`). The value displayed is **"À vérifier"** — no estimate exists. The adjective *estimée* implies a computed figure, which contradicts the evidence-quarantine intent. A user glancing at the label+value pair may believe a hidden estimate exists. Fix: use a neutral label such as `futurRenteLpp` → "Rente LPP" (drop "estimée") or introduce a dedicated `futurRenteLppPending` key.

**Severity note:** Not P1 because the value cell explicitly says "À vérifier" and the CTA makes the pending state visible. No CHF amount is shown.

### P2-B · `civilStatus == 'marie'` in LPP buyback strategy (pre-existing, not introduced by diff)

**File:** `apps/mobile/lib/services/financial_report_service.dart:288`
```dart
final isMarried = profile.civilStatus == 'marie';
```
The model uses `'married'` (`UserProfile.isMarried` at `financial_report.dart:86`). The service uses `'marie'` (French string). Married users will always be evaluated at the single rate for LPP buy-back marginal-tax savings. Tax savings will be underestimated for married users. Pre-existing; not introduced by this diff. No test covers this path.

**Reproduction:** Construct a married profile (`civilStatus: 'married'`), call `_buildLppStrategy`. `isMarried` evaluates `false`. The strategy uses single-rate marginal tax.

---

### P2-C · Retirement age hardcoded to 65 for all users (pre-existing, AVS21 exposure)

**File:** `apps/mobile/lib/models/financial_report.dart:85`
```dart
int get yearsToRetirement => 65 - age;
```
AVS21 transitions women's reference age from 64 to 65 gradually through 2028 (64y3m → 64y6m → 64y9m → 65). Any woman born 1961–1964 currently has a reference age below 65. This affects `yearsToRetirement` used in LPP buy-back horizon calculation. Pre-existing; not introduced by this diff. Since no AVS/LPP amounts are displayed without evidence, the user cannot make a financially harmful decision from this field alone in this diff's context — hence P2 not P1.

## MINT product logic review

**Evidence quarantine (ledger → DataQuest → scenario → dossier spine)**
The diff correctly propagates the fail-closed evidence model through all four layers:
- **Model layer**: `RetirementProjection` fields nullable; `totalCapital` and `totalMonthlyIncome` computed as `null` if any component unknown (`financial_report.dart:151–156`).
- **Service layer**: `_buildRetirementProjection` returns all pension values as `null`; estimation methods deleted (`financial_report_service.dart`).
- **Display layer**: `RetirementProjectionCard` is unconditional — always shows 3 pending blocks regardless of model field state. A non-null `monthlyAvsRent` in the model (as in the widget test at `retirement_projection_card_test.dart:19`) is silently quarantined at the widget level and never rendered as CHF. This is correct per the evidence-quarantine contract, though the model field being writable while the widget ignores it may confuse future contributors.
- **PDF layer**: Section 5 reads only `l.coverageCheckAVerifier` ("À vérifier") for all pension/capital rows. No raw field access from `RetirementProjection` (`pdf_service.dart:717–740`).

**Routing integrity**
Three routes verified at compile-time (widget test + Maestro + Patrol):
- `/scan/avs-guide` — official AVS statement order
- `/scan` with `extra: DocumentType.lppCertificate` — LPP certificate scan
- `/data-block/3a` — 3a data entry

Route declarations match GoRouter configuration. Negative route assertions in Maestro (`financial_report_avs_amount`, `financial_report_retirement_total`, `financial_report_replacement_rate` not visible) correctly gate the old estimated values.

**Contract coverage**
Four contract test files (Python AST-level + Dart source-level) guard against regression to the pre-existing P0:
- `test_g1_avs_certified_null_contract.py` — source-level absence of synthesis tokens
- `financial_report_3a_quarantine_contract_test.dart` — model/service/screen/PDF absence of `Pillar3aAnalysis`
- `financial_report_g1_contract_test.dart` — PDF localized key wiring
- `retirement_projection_contract_test.dart` — `totalCapital` null propagation

The contract suite is fail-closed: tests verify absence of forbidden patterns, not only presence of correct ones. This is the right approach for an evidence-quarantine model.

**Remaining gap**: `LppBuybackStrategy` still generates CHF tax-savings amounts from canton-level marginal rate tables. This path is not modified by the diff and is not evaluated here. It should be in scope for the next domain audit pass.
