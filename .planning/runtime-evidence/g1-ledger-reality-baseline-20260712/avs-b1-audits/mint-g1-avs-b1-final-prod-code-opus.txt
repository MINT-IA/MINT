### P0-2 · Certificate-gating ships with no test coverage; existing golden-path tests would fail at runtime even after a null-safety fix
The new gate is `avsIncluded = profile.avsGapEvidence.householdReady` (`retirement_projection_service.dart:206`), and `householdReady` requires `selfCertifiedYears != null`, i.e. `dataSources['prevoyance.lacunesAVS'] == ProfileDataSource.certificate` (`coach_profile.dart:77-78`, `2014-2021`).

The projection tests build profiles that set **neither `lacunesAVS` nor a certificate `dataSource`** (`test/services/retirement_projection_service_test.dart:38-41` `buildProfile`; the root test likewise). Grep confirms none of the three broken test files reference `dataSources`, `certificate`, `householdReady`, or `avsIncluded`. For those profiles `householdReady == false`, so post-change:
- `revenuMensuelAt65 == null` → `expect(result.revenuMensuelAt65, greaterThan(0))` (line 61) fails,
- `budgetGap == null` → the `budget gap includes all income sources` test null-derefs,
- `earlyRetirementComparisons == const []` → `expect(...length, equals(8))` fails,
- `indexedProjection == const []` → `expect(...length, equals(26))` fails.

So even after patching `?.`/`!`, the suite would go red. The behavior change (AVS excluded unless certificate-sourced) has **no positive or negative test** in the projection service suite. This is exactly a facade-without-verification risk: the gate exists in production but nothing proves it fires correctly, nor that certified profiles still produce full projections.

To make this pass properly, the projection tests must (a) supply `dataSources: {AvsGapEvidence.selfFieldPath: ProfileDataSource.certificate}` (+ spouse path for couples) with a `lacunesAVS` value, and (b) add explicit coverage of the `avsIncluded == false` path (null income, null gap, empty phases/scenarios/indexed).
