## P2 (pre-existing, surfaced by the audit but not caused by this diff)
- **Static confidence figure not justified by data state** — `apps/mobile/lib/screens/mortgage/affordability_screen.dart:281` hardcodes `percent: 45` on the affordability confidence notice. This value is fixed regardless of how many of the four inputs (revenu, LPP, épargne, canton) are actually known vs. estimated — even the auto-fill path (`_initializeFromProfile`, lines 55-95) that can populate real profile values leaves confidence at 45. The métier requirement "distinguish known/missing/estimated, and justify confidence" is not met: the number is a facade. Not introduced here, but the diff makes this CTA more prominent/actionable, so it is worth fixing next.
- **Enrich CTA narrows to salary only** — `affordability_screen.dart:284-292` the "améliorer mes données" action routes to `/data-block/revenu` with `inputKey: 'q_gross_salary_annual'` only. The low-confidence signal spans equity, LPP and canton too, so tapping "enrich" and returning will not move the (hardcoded) confidence, which can feel like a dead-end. Pre-existing; consider routing to the missing-input the ledger actually reports as lowest quality.
- **Duplicate identifier string** — the same literal `'mortgage_enrich_profile_cta'` is used for both the widget `Key` (line 280) and `actionSemanticsIdentifier` (line 284). Harmless, but the file-scan test at `mint_confidence_notice_test.dart:45-56` couples the source text to that literal, so any future rename must touch three places.
