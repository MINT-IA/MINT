## Product/domain verdict: PASS

This unstaged change is an accessibility/semantics-only refactor of the "enrich" CTA on the disability gap screen. It wraps the existing `TextButton.icon` in `MergeSemantics` + `Semantics(identifier: 'disability_gap_enrich_cta', button: true)` and upgrades the routing test to assert the CTA exposes a single tappable button node contained within the ledger-facts card. No Swiss financial logic, constants, routing targets, or compliance copy were changed.

### Findings

**P0** — none.

**P1** — none. The change does not touch any Swiss-law-sensitive constant, calculator, or advice surface. All domain logic (`DisabilityInsuranceCalculator`, LAI/LPP/LAMal grades, emergency-reserve months) is untouched by this diff.

**P2**
- `disability_gap_screen.dart:538` — the `Key('disability_gap_enrich_cta')` now lives on the inner `TextButton` while the same string is used as the `Semantics.identifier` on the wrapper. It works (the older test at `disability_gap_ledger_test.dart:315` still finds the key; the new test finds the identifier), but the doubled name is a mild maintenance smell — a reader can't tell at a glance whether tests target the widget key or the semantics node. Consider distinct names.
- `disability_gap_ledger_test.dart:283-288` — the new geometric assertions (enrich rect contained in ledger rect, area strictly smaller) are layout-coupled and could become brittle under theme/padding changes. Acceptable for an a11y-containment guard, but flag as fragile.
- Pre-existing (not introduced here, so not blocking this diff): the "nothing missing" branch routes the CTA to edit `q_gross_salary_annual` (`:502`) rather than offering to edit whichever fact the user most likely wants; a fact-row-level edit affordance would be more coherent with the ledger model. Out of scope for this change.
