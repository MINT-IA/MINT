### P2 Findings

**P2 — Diagnostic message lost on cleanup retry**
`tools/simulator/patrol_return01_six_origin.sh:217-222`

**Description:** When `restore_normal_build` fails the absence check (`get_app_container` returns 0, meaning seeded app is still installed), it appends the line `"seeded app remained installed after restoration uninstall"` to `$private_root/restoration-uninstall.raw.log` via `>>`, then returns 1. If `cleanup()` then retries `restore_normal_build`, the second `xcrun simctl uninstall` call redirects output with `>` (truncate), silently overwriting the raw log and losing the first call's diagnostic message.

**Reproduction path:**
1. Seeded app install somehow survives `xcrun simctl uninstall` on first call.
2. `restore_normal_build` appends the diagnostic line and returns 1.
3. `cleanup()` retries: second call's `>"$private_root/restoration-uninstall.raw.log"` truncates the file; first call's message is gone.

**Impact:** Cosmetic only — this is already a failed run path with no metadata written. The correctness invariant (app restored or `cleanup_failed=1`) is maintained.
