### P2 (accept-with-note; no blocker)

1. **Idempotency guarantee weakened for stateful gates** — `documents.py:468-498` (entitlement 2-doc gate, 100-doc cap) now runs *before* the deferred cache lookup (`:569`). Previously cache replay was the first action. Repro: free user uploads their 2nd doc successfully (count→2, response cached), first response is lost, client retries with the same `Idempotency-Key`; the retry now hits `doc_count >= 2 → 403` (`:475-479`) instead of the cached 200. Same class for the 100-doc cap. Narrow edge case, no privacy/security impact, and it is a deliberate consequence of the privacy-motivated reordering — acceptable, but worth documenting the changed idempotency contract.

2. **Stale secondary artifact `tools/openapi/openapi.json`** — still shows `raw_text_preview` as `{type: string, default: ""}` and the old doc-type description (`openapi.json:16288-16292`). It is not regenerated by `generate_canonical.py` and I found no code/tooling consumer, so it is pre-existing housekeeping drift now widened by this change. Recommend regenerating or deleting it to avoid future confusion.

3. **Pre-existing global SHA cache is cross-user (not introduced here)** — for non-`lpp_plan` durable docs, `lookup_by_file_sha` (`:576`) is keyed on content only, so identical bytes across users can return another user's `id`/preview. Content is identical by construction and `GET` re-filters by `user_id` (404), so impact is minimal; the diff's own comment acknowledges this. Out of scope for this diff's verdict; flagging for the backlog.
