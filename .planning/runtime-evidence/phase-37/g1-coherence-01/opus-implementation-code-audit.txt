### P1
**1. G1-RETURN-01 work-origin runtime proof is now unreproducible, and its guard test gives false-green.**
The rewrite (a) gates `/first-job` fail-closed, (b) **renames** the stable selector `first_job_result_cards` → `first_job_salary_authority`, and (c) makes `first_job_ledger_facts` render **only** in the incomplete-facts branch (`first_job_screen.dart` `_missingFactsCard`, `key: Key('first_job_ledger_facts')`, rendered iff `result == null`; complete state uses `first_job_salary_authority`). The proof artifacts were **not** updated:
- `.maestro/g1_return01_work_return.yaml:9,24,54,57` — still `openLink: "mint:///first-job"`, waits on `first_job_ledger_facts`, taps `first_job_result_cards`.
- `integration_test/g1_return01_first_job_return_patrol_test.dart:39-88` — `go('/first-job')`, expects `FirstJobScreen` visible (line 42) and `Key('first_job_result_cards')` (line 86-88).
- `test/runtime/g1_return01_six_origin_runtime_test.dart:130,253` — asserts the YAML still contains `first_job_result_cards` / `first_job_ledger_facts`, so it **passes** while enforcing selectors the app no longer produces.

Reproduction:
- Run the patrol flow with `MINT_PATROL_CLI=true`: shipped defaults redirect `/first-job` → `/explore/travail`, so `find.byType(FirstJobScreen).waitUntilVisible()` (line 42) can never succeed. Even forcing `MINT_TEST_FIRST_JOB=true`, line 86-88 fails — the rewritten screen never builds `Key('first_job_result_cards')`.
- The patrol test is `skip: !_runningFromPatrolCli` (default skipped), so `flutter test` silently passes it; the six-origin guard only scans stale YAML text, so CI stays green. Net: the "capital-native proof" for the work origin is misrepresented as passing.

Impact bound: this does **not** affect shipped behavior (route is intentionally fail-closed) — it is a test-integrity / facade-in-the-test-layer defect. Fix: update or explicitly retire the work-origin Maestro flow + patrol test + six-origin guard to the new selectors / fail-closed reality, so the guard cannot be green while the flow is dead.

### Verdict
# NO-GO

The product change itself (honest salary model, fail-closed route, removal of fabricated net/employer-cost/"recommended franchise" facade) is clean and well-tested. The blocker is P1: this branch's stated deliverable is a runtime *proof*, and the change silently invalidates the work-origin proof while a guard test continues to report success against selectors that no longer exist. Re-align the Maestro flow, the patrol integration test, and `g1_return01_six_origin_runtime_test.dart` with the new selectors / fail-closed route (or explicitly retire the work origin from the six-origin proof), then this is a clear PASS.
