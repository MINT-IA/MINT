## What the flow clarifies
Life event: entering the workforce / first Swiss salary. The Swiss decision it now frames honestly: "what is actually deducted from my gross, what is only illustrative, and what must I confirm with primary documents (payslip, LPP certificate, Priminfo)." It no longer pretends to output an exact net, an employee LPP figure, a franchise recommendation, or a wealth projection.

## P1 — none
The previously shippable version contained P0/P1-grade problems that this diff **removes**, which is why the net verdict is PASS:
- Fabricated employee LPP as `bonification/2` and a derived exact net (`first_job_service.dart` old lines) — the new model returns `lppEmploye: null` and `netEstime: null` and states "This is not your pension deduction" (`app_en.arb` `firstJobLppIllustration`; enforced by `first_job_service_test.dart:` "never converts an age credit into an employee LPP deduction").
- Product recommendation / ranking: franchise `2500` as `franchiseRecommandee`, and advice strings "Évite les 3a liés à une assurance-vie", "Privilégie un 3a fintech" — all deleted; replaced by neutral `firstJobPillar3aNeutralBody` / `firstJobLamalNeutralBody` ("MINT ranks no deductible without those inputs").
- Malformed Swiss number formatting in the old projection (`'${fv.round() ~/ 1000}\'000'` → "1641'000") — removed; `first_job_whole_screen_coherence_test.dart` asserts the canonical formatter.

## P2
- **Dead entry point in the degraded state.** With the flag off, `/first-job` redirects to `/explore/travail` (`app.dart:2436` `firstJobFeatureRedirect`), but that hub still advertises `HubEntry(label: 'Premier emploi', route: '/first-job')` (`app.dart:1362`). In production a user tapping "Premier emploi" is silently bounced back to the same hub. Dormancy is intentional and documented, but the hub tile should be hidden or disabled while the feature is fail-closed to avoid a facade tile.
- **Over-cautious labeling of exact statutory rates.** AVS/AI/APG (5.3%) and AC (1.1%) are legally fixed employee rates, yet grouped under `firstJobKnownDeductionsIllustrative` ("Illustrative statutory contributions"). This *understates* certainty (safe direction), but AANP (1.3%, genuinely variable) and the two fixed rates deserve different confidence framing rather than one "illustrative" bucket.
- **Constant provenance not proven in-diff.** `_avsAiApgRate=0.053`, `_aanpIllustrativeRate=0.013` are literals; LPP `lppSeuilEntree=22680` / `lppDeductionCoordination=26460` come from `social_insurance.dart`. These match 2025 values (which hold for 2026, no AVS re-indexation in an off-year), so not stale — but only the LPP path feeds a *labeled illustration*, never a hard figure the user acts on, so residual risk is low. Would be proven by a dated source reference next to the constants.
