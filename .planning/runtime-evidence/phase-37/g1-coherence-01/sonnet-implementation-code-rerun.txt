### P1 — Maestro proof broken: `_enrichmentCta` drops its semantic identifier

**File:** `apps/mobile/lib/screens/first_job_screen.dart:201-212`

```dart
Widget _enrichmentCta(BuildContext context, S s) => Container(
      key: const Key('first_job_enrich_profile_cta'),   // widget key only
      alignment: Alignment.centerLeft,
      child: TextButton.icon(
        onPressed: () { ... context.push(_revenueRoute()); },
        icon: const Icon(Icons.fact_check_outlined),
        label: Text(s.firstJobEvidenceHint),
      ),
    );
```

The Maestro flow `.maestro/g1_return01_work_return.yaml:23-28` depends on:

```yaml
- extendedWaitUntil:
    visible:
      id: "first_job_enrich_profile_cta"
    timeout: 20000
- tapOn:
    id: "first_job_enrich_profile_cta"
```

Maestro's `id:` resolves against the iOS `accessibilityIdentifier`, which in Flutter comes from `Semantics(identifier: ...)`. A plain `Container` with only a widget `Key` does **not** produce an accessibility identifier. Every other Maestro-targeted widget in the codebase uses an explicit semantics wrapper — confirmed via `data_block_enrichment_screen.dart` where `_buildRevenueTextField` is defined as `Semantics(identifier: semanticsIdentifier, child: TextField(key: key, ...))`.

The runtime test (`g1_return01_six_origin_runtime_test.dart`) checks that `first_job_salary_authority` has both a key and an identifier (line-level assertions). It never checks `first_job_enrich_profile_cta`. The gap is unguarded.

**The old code had the identifier explicitly:**

```dart
// removed by this diff:
Semantics(
  key: const Key('first_job_enrich_profile_cta'),
  identifier: 'first_job_enrich_profile_cta',
  button: true,
  child: TextButton.icon(...),
)
```

**Reproduction:**
1. Build with `--dart-define=MINT_TEST_FIRST_JOB=true`
2. Install on simulator and run `maestro test .maestro/g1_return01_work_return.yaml`
3. `extendedWaitUntil visible id: "first_job_enrich_profile_cta"` times out after 20 s — the accessibility identifier is absent from the semantic tree
4. Maestro exits non-zero; the `work_save` G1 proof cannot be generated

**Required fix:** Restore the `Semantics` wrapper on `_enrichmentCta`:

```dart
Widget _enrichmentCta(BuildContext context, S s) => Semantics(
      key: const Key('first_job_enrich_profile_cta'),
      identifier: 'first_job_enrich_profile_cta',
      button: true,
      child: Container(
        alignment: Alignment.centerLeft,
        child: TextButton.icon(
          onPressed: () { _hasUserInteracted = true; context.push(_revenueRoute()); },
          icon: const Icon(Icons.fact_check_outlined),
          label: Text(s.firstJobEvidenceHint),
        ),
      ),
    );
```
